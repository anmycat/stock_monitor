## 一、结论先行

**这不是量化方法论，是面向中国企业老板/中高层的人力资源管理培训课件。** 直接内容（销售提成、计件工资、
职级薪酬带、福利体系、社保与劳动仲裁、员工定位 A1-E6）与本项目（个人 A 股量化投研系统）**基本无关**。

但它提供了 **3 个可迁移的结构性范式**，其中 1 个恰好命中项目当前**已被核实存在的真实缺口**：

| # | 课件结构范式 | 课件原始形态 | 本项目对应点 | 命中缺口？ |
|---|---|---|---|---|
| ① | **系数化 + 延迟发放** | 销售达标但回款率低 → 按系数（0.5/0.8/1.0）发放，**剩余部分延迟至款项收回后再发**（第一讲 P19 奖金池表） | `PostEvaluation` 的 T+N 后验评估（pnl / win_rate / max_drawdown）→ **反哺信号权重** | ✅ **命中，且已核实为 0 链路** |
| ② | **过程考核 / 结果考核分离** | 薪酬 = 固定 + 绩效（**过程考核**）+ 结果考核 + 年终奖（第一讲 P15） | 系统过程纪律（非交易时段零触网 / 冷却 / 熔断 / 降级链遵守率）→ 作为**结果可信度的前置维度** | 🟡 部分命中（数据已具备，未成维度） |
| ③ | **按质量分档，而非按绝对值一刀切** | 销售提成由"无论多少都 1%"改为**按毛利率分档**：<0→0、0-15%→0.2%、15-20%→0.6%、20-40%→1.0%、>40%→1.2%（第二天 P4） | 多因子关键维度（资金流 / 量能）由连续加权改为**离散档位系数** | 🟡 理论命中，改动风险高 |

## 二、项目侧现状核验（全部实测，非记忆）

> 核验时间 2026-11-06，仓库 HEAD `e414834`。

### 2.1 后验评估 → 信号权重：**零反哺**（对应范式 ①）

```
grep 全仓 quant_engine/** + research/rules/*.json：
同时命中 (eval_result|post_eval|eval_runs) 与 (kelly|weight|factor|adjust) 的行 → 0 行
```

`quant_engine/backtest/post_evaluation.py`（223 行）产出 `pnl`(14 处) / `win_rate`(6) / `max_drawdown`(8)，
写入 `eval_runs` / `eval_results` 两表（`data/store.py`），并经 `/api/evaluation/runs` 暴露；
但**没有任何一处把评估结果回写进 `kelly_position` / `level_factor` / rules JSON**。

**这是本轮评估中唯一被证实的"真缺口"**：评估链只做归档，不参与决策。

### 2.2 信号级别：**无强制分布**（对应范式 ③ 的背景）

- `models/signal.py`：`level_factor` = S→1.0 / A→0.7 / B→0.4，`level is None` → 0.5
- 级别来源为**策略分阈值**（`strategies/trend.py` `_determine_level`：≥80 S、≥70 A、else B），
  `strategies/dispatcher.py` 融合后按融合分重新定级（D47 修过一次"63.5 分挂 B 级"的 level 不同步缺陷）
- `research/rules/methodology_rules.json`：**无**任何 distribution / quota / percentile / truncation 约束
  （grep 命中的 `distribution_risk`、`C03_high_distribution` 均为"筹码分布"，无关）
- 实测分布：129 日 × 27 票 → 552 笔信号，其中 **174 笔推送（31.5%）**

### 2.3 过程纪律数据：**已具备**（对应范式 ②）

`data/source_manager.py::get_status_report()` 为每个源提供：
`available` / `error_count` / `empty_count` / `request_count` / `success_count` /
`cooldown_until` / `quarantined_until` / `quarantined`（空结果与真实错误已分离计数，D53 成果）
→ 已在 `GET /api/health` 的 `data_sources` 面板暴露。

## 三、三个可迁移范式的落地建议（按性价比排序）

### 建议 1（P0，最高价值）：后验评估反哺 —— 建"降权观察期"，而非直接改权重

**课件机制**：销售达标但回款率低 → 不全发，**剩余部分延迟至款项实际收回后再发**。
课件写明理由：**"关联回款率是为了确保公司资金链的正常运转"** —— 即：用**兑现条件**约束**发放节奏**，
而不是用单次结果立即惩罚/奖励。

**项目对应**：信号 T 日产生 → T+N 后验评估（`eval_results`）→ 若该策略/该市场状态下偏差超阈值，
**后续同源信号进入降权观察期**（仓位打折或暂停推送），**不立即改 rules JSON**。

**为什么这是对的（三个理由）**：
1. 与项目既有纪律一致：rules JSON 升/降版需用户确认（D28「文档裁定 → 用户确认 → 配置合入」中间态）；
   "延迟发放"正是**不破坏该纪律**就能落地的机制。
2. 避免**单笔噪声 overreact**：半年窗口 614 笔信号，任何单笔结果都不足以改权重；
   观察期天然是"样本累积到 N 笔才生效"的缓冲。
3. 数据已齐：`eval_runs`/`eval_results` 表 + `/api/evaluation/runs` 端点现成，缺的是**归因 → 权重**这一段。

**落地形态建议（不动现有信号逻辑）**：
- 新增独立观测层：Redis `eval_feedback:{strategy}:{market_type}` 记录近 N 次评估结论
- 降权**只作用于仓位与推送**，不写回策略/规则（保持 D41 回归的"信号不变"性质）
- 观察期状态在 **D61 日报**里以独立字段呈现（"信号可信度：观察期中 / 正常"）→ 延续"客观判定由代码算出"原则

**风险等级**：中。改动仓位/推送而非信号本身 → 仍需 D41 双跑（129 日 × 27 票）证明信号零漂移。

### 建议 2（P1，低风险）：过程考核作为日报的"结果可信度"前置维度

**课件机制**：绩效工资考**过程**（行为/纪律），奖金考**结果**（目标达成）；两者分离。

**项目对应**：D61 日报当前 5 维综合分 = 市场类型 / 趋势结构 / 市场宽度 / 量能配合 / 信号质量
—— **全部是"结果"维度，零"过程"维度**。可加第 6 维（或前置校验）：
**过程纪律**：当日是否发生非交易时段触网 / 源降级 / 熔断 / 冷却误伤 / 代码一致性告警。

数据源现成：`/api/health` 的 `data_sources` 状态面板 + worker 日志 + CodeGuard 报告。

**为什么值得做**：D61 的设计铁律是"客观判定由代码算出、不交给模型发挥"。
过程纪律是**客观**的（可从 Redis/日志直读），且它决定了**结果数据可不可信** ——
例如当日东财全线熔断，则"市场宽度 38.7%"这个结果本身就打折。**这是当前日报的一个真实盲点。**

**风险等级**：低。只加展示维度，不动信号链 → 无需双跑回归。

### 建议 3（P2，谨慎）：关键因子离散分档系数

**课件机制**：按毛利率分档给不同提成比例，取代"一刀切 1%"。

**项目对应**：多因子融合中权重最高、最易失真的**资金流（13%）与量能（10%）**由连续加权改为离散档位。

**为什么不建议现在做**：
- 连续加权是**已验证口径**（D33 三窗口 195 笔定稿），改档位等于**重开半年验证窗口**
- 离散档位会**丢失档间信息**，与"多因子连续加权"的初衷相反；收益不确定
- 若要试，**只能加在维度内部作为辅乘**，不替换现有加权；且必须双跑 + 用户确认

**风险等级**：高 → **本轮不立项**，登记为待观察项。

## 五、课件方法论中"元层"的三条印证（对项目现有设计是验证，不是改动）

1. **"战略决定命运，战术决定成败；绩效决定战术，氛围决定绩效"**（第一讲 P29）
   → 项目两轨结构（产品线 = 战术执行、调研线 = 战略方法论）**恰好印证**了双轨并列的合理性。
2. **"不要全员考核"**（P27）→ 项目三层漏斗已正确。
3. **"薪酬体系与法律风险防范：制度先行、明确计算方式与发放时间"**（第二天 P9）
   → 项目信号卡/日报的**可核对、可回看、可留痕**要求（`/api/report/raw` + `summaries` 归档）已由 D61 落地。

**反过来说，课件没给项目任何"量化"能力**——没有因子、阈值、样本、验证方法论。
项目的核心资产（半年窗口 614 笔 / 三窗口复验 / Kelly 下修 / 牛熊分段）**必须继续自建**，
不能指望从 HR 课件里借。**本报告的价值只有"结构范式迁移"这一层，不含任何可直接套用的参数。**
