## 2. 「停止」考证结论：**从未停止，是三重误读**

按调研纪律逐条核对 git 历史 / PRD / research docs / 现网代码，结论如下（每条附证据）：

| 误读 | 事实 | 证据 |
|---|---|---|
| "模块被下线/删除" | 代码全线在线：worker 调度、API 四端点、前端卡片、测试均未删除/未注释 | `worker.py:146-184,389-390`；`routers/etf.py`；`UX/static/index.html:366`；`test/test_etf_holdings.py` |
| "有过停止裁定" | **无任何停止/判定无用的记录**；git log、docs/42（完成度审计）、docs/43（23 项裁定）全文无 ETF 停止项 | `research/docs/42`、`docs/43` 全文检索 |
| "功能被降级" | 仅两件事：① **D53 调度整改**——从"盘后/周末每分钟唤醒触网"改为"交易日 9:00-9:30 盘前窗口"，属效率/合规修正；② **docs/28 阈值调参暂缓**——因缺实盘证据，C 线（ETF diff）首季数据未积累（至 2027-01-31），首月只调 D/E 线。对象是**调参**不是模块 | commit `04f5224`；`docs/28:40-43` |
| "历史故障暗示被放弃" | D50 曾发现 `fund_holdings.py:63` 相对导入少一层点致抓取静默失效，D52 已修复并加回归（非主动停止） | `prd/manifest.json:522-526`；commit `4fc855a6`；`test_etf_holdings.py:269-287` |

**根因判断（为什么用户感觉"停止了"）**：三个真实缺陷叠加导致"看不见产出"：
1. **前端死角**：持仓监控有 4 个 API 端点、worker 每日写 Redis，但 `UX/static/index.html` 的 ETF 卡片只渲染 `/api/etf` 实时行情，**从未调用任何 `/api/etf/holdings*`**（grep 全文无路径）。功能在跑但用户看不到。
2. **季频天然低频**：jjcc 季度持仓一年更新 4 次；`refresh_etf` 数据陈旧时返回 None，`:changes` 键长期停留最近一次有 diff 的季度——看起来像"不动了"。
3. **数据源能力天花板**：`fund_holdings.py` 的东财 F10 jjcc 只有季度持仓（代码/名称/权重/持股数/市值），**无涨跌、成交额、规模、分红**；仅靠 diff 告警，缺少"看板价值"。

**诚实边界**：仓库内无生产日志/Redis 实盘导出，无法证实 `etf_holdings:*` 当前是否有产出；以上"前端死角/低频"为代码事实，"用户感知停止"为推断。
