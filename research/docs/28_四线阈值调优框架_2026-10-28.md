## 2. 数据基础（调优的证据来源）

| 证据 | 来源 | 频率 |
|---|---|---|
| 信号 T+5/T+10 前向收益归月 | `research/scripts/monthly_recheck.py`（SQLite signals 归档） | 每月 1 日 |
| 单轮信号质量 | Redis `run:*` / SQLite `eval_results`（后验评估） | 每日 |
| 新闻推送构成 | Redis `news:check_date` + 钉钉历史（板块分布/限量截断） | 每日 9:15 后 |
| ETF 持仓 diff | API `/api/etf/holdings/{code}/changes` | 每季 |
| CodeGuard 报告 | `GET /api/system/code-guard/report` + 钉钉"代码一致性"推送 | 每日 9:00-9:15 |
| 源健康度 | `/api/health` 源状态面板 + worker 日志降级 warning | 持续 |

**注意**：D 线新闻构成与 C 线 ETF diff 的量化证据依赖生产运行积累
（SQLite signals 表自 2026-10-25 起全量落库；eval_results 自 10-25 起）。
**首月（至 2026-11-30）只调 D/E 两线的字典与限量类参数**（证据周期短、
改动面小、可回滚）；C/F 两线等首季数据（至 2027-01-31）再动。

## 3. 调优节奏与门禁

| 时点 | 动作 | 门禁 |
|---|---|---|
| 每月 1 日 | 跑 `monthly_recheck.py`，出月度复验报告 | 连续两月均盈亏 >0 → 恢复标准仓位（14 §4） |
| 2026-11-30（首月末） | D/E 两线小参调优评审（限量/字典/跳变阈值） | 单次只调一条线的至多两个参数；改动后 5 个交易日观察窗 |
| 2027-01-31（首季末） | C/F 两线评审 + 全四线阈值定调 | 阈值变更须附双窗口证据（与 D41 回归纪律同标准） |
| 每季滚动 | 复跑本框架 §1 清单核对触发条件 | 无触发条件命中则不动（防止过度拟合） |

## 4. 调优操作流程（单参数）

1. **立项**：在 prd/ 对应模块文档（07 §15 / 08 §10-13）登记"参数 X 拟从 a → b"，
   附证据（哪几日、多少样本、什么现象）——**文档中间态**（D28）。
2. **实现**：改代码 + 补/改测试（阈值测试随参数同步）；ruff + 全量测试 + 架构审计。
3. **回归**：信号回归双跑对比（D41：129 日 × 27 票，git worktree 跑 HEAD 基线），
   trend.py 类因子改动须逐票对账。
4. **合入**：用户确认后随部署上线；部署后 5 个交易日观察窗内每日核对触发指标。
5. **归档**：结果写回 prd/ 对应小节（通过/回滚），manifest 升版。

**回滚线**：观察窗内触发指标恶化 >50% 或出现新误报类型 → 立即回滚并登记。

## 5. 与其他纪律的关系

- **D28（rules JSON）**：本文所有参数**不涉及** rules JSON；Kelly 口径调整
  仍走 06 §3.1 + 用户确认流程（v1.7 建议见 docs/23，待确认中）。
- **D41（信号回归）**：凡影响信号产出路径的改动（E 线价格阈值会影响
  bad_price 检出 → 缓存清理 → 报价可用性），必须双跑对比。
- **D47（信号价/级别同源）**：调优不得破坏"信号价 = 信号生成日收盘价"与
  S/A/B 级别同源重算的不变式。
- **月度复验门禁**：调优的终极裁判是月度复验的连续两月盈亏；单线参数
  收益不能以牺牲整体胜率为代价（R02 教训：单规则尖兵不可外推，09 §8 第 9 条）。
