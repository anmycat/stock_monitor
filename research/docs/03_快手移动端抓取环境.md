目标：抓取快手账号 **多空博弈社（快手号 `qianmoQ2020`）** 的全部作品。
本文档记录已构建的抓取环境、技术发现与使用方法。

## 一、环境组件

| 组件 | 说明 | 位置 |
|---|---|---|
| 桌面 Chrome 实例 | 端口 **9222**，profile `/tmp/ksprofile`，已登录（账号"喵个咪喵"） | 内容抓取主力 |
| 移动端 Chrome 实例 | 端口 **9223**，profile `/tmp/ksmobile`，iPhone UA + 390×844 视口 | 移动端环境验证 |
| CDP 基础库 | 标签页管理 / 导航 / JS 求值 | `scripts/cdp.py` |
| 移动端模拟库 | 设备指纹注入 + 触摸 + **网络响应拦截** | `scripts/ks_mobile.py` |
| 登录助手 | 登录页唤起 / 登录态检测 / cookie 导出 | `scripts/ks_login.py` |
| REST 探测器 | 在页面上下文内调接口 | `scripts/ks_api.py` |
| 作品抓取器 | 页面驱动 + 响应拦截 + 分页汇总 | `scripts/fetch_kuaishou.py` |

### 启动命令

```bash
# 移动端实例（iPhone 指纹）
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --remote-debugging-port=9223 --user-data-dir=/tmp/ksmobile \
  --user-agent="Mozilla/5.0 (iPhone; CPU iPhone OS 17_6 like Mac OS X) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/17.6 Mobile/15E148 Safari/604.1" \
  --window-size=390,844 --no-sandbox --disable-gpu --disable-dev-shm-usage &

# 桌面实例（内容抓取，保留登录态）
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --remote-debugging-port=9222 --user-data-dir=/tmp/ksprofile \
  --no-sandbox --disable-gpu --disable-dev-shm-usage &
```

> ⚠️ macOS 上必须加 `--no-sandbox`，否则 Chrome 沙箱初始化失败、network service 崩溃退出。

### 移动端指纹注入（已验证生效）

`Emulation.setUserAgentOverride` + `setDeviceMetricsOverride` + `setTouchEmulationEnabled`，实测结果：

```
ua: Mozilla/5.0 (iPhone; CPU iPhone OS 17_6 ...) Version/17.6 Mobile/15E148 Safari/604.1
platform: iPhone   touch: 5   viewport: 390×844   dpr: 3
```

内置两套预设：`iphone`（390×844 dpr 3）与 `android`（412×915 dpr 2.625）。

## 二、关键技术发现

### 1. 快手对移动浏览器强制「跳下载页」

| 入口 | 结果 |
|---|---|
| `m.kuaishou.com` | App 下载落地页，无内容 |
| `m.kuaishou.com/u/qianmoQ2020` | 路由有效，但返回「服务器繁忙，请稍后再试」 |
| `www.kuaishou.com/profile/...` + iPhone UA | **302 跳到** `m.kuaishou.com` 下载页 |
| `www.kuaishou.com/profile/...` + Android UA | 同样跳下载页 |

结论：模拟手机浏览器这条路被快手商业策略堵死——它只想让你装 App。**移动端 UA 反而比桌面 UA 能拿到的更少。**

### 2. 真实内容接口是 REST，不是 GraphQL

拦截发现的接口（均为 `https://www.kuaishou.com`，带 cookie 同源）：

```
/rest/v/search/user   ?keyword=...&pcursor=...&__NS_hxfalcon=...
/rest/v/search/feed   ?keyword=...&pcursor=...
/rest/v/profile/get   ?userId=...
/rest/v/profile/photolist  ?userId=...&pcursor=...&page=profile
```

### 3. 签名绑定参数，无法脱离页面构造请求

直接 `fetch()` 复用抓到的 `__NS_hxfalcon` 值：

```json
{"result": 50, "ab8d": true, "error_msg": "签名验证失败"}
```

该 token 与请求参数绑定。**唯一可行方式是让页面 JS 自己发请求**（签名由页面生成），再用 CDP `Network.getResponseBody` 拦截响应——这也是本环境的核心设计。

### 4. 作品列表接口存在风控

桌面已登录态下访问 `/profile/{任意账号}` 固定返回「服务器异常，稍后重试」，换其他博主验证结论一致 → **网页端作品列表接口当前是全局限流，不是登录问题**。

## 三、使用方法

```bash
PY=/Users/hr.wh/.workbuddy/binaries/python/envs/default/bin/python

# 环境自检（UA / 视口 / 登录态）
$PY scripts/ks_mobile.py probe --url https://m.kuaishou.com/

# 登录（如登录态失效）
$PY scripts/ks_login.py open
$PY scripts/ks_login.py check      # 确认登录态
$PY scripts/ks_login.py cookie     # 导出 cookie

# 抓取作品（页面驱动 + 拦截）
KS_PORT=9222 $PY scripts/fetch_kuaishou.py profile qianmoQ2020 --scroll 30

# 搜索账号
KS_PORT=9222 $PY scripts/fetch_kuaishou.py search 多空博弈社

# 查看某页触发了哪些接口
KS_PORT=9222 $PY scripts/fetch_kuaishou.py urls https://www.kuaishou.com/new-reco
```

切到移动端实例只需把 `KS_PORT` 改成 `9223`。

## 四、如果要走真机路线（未启用）

上述浏览器方案若始终拿不到作品列表，剩下的唯一可靠路径是**真机/模拟器 + 抓包**：

1. Android 模拟器（本机**无** Android SDK / 模拟器 / adb / mitmproxy，需下载数 GB）
2. 安装快手 App 并登录
3. mitmproxy 抓包 → **但快手 App 有 SSL Pinning**，需 Frida / Objection 绕过证书绑定
4. 逆向 `restphotolist` 接口签名

成本很高且涉及客户端逆向，除非确实必需，否则推荐改用以下替代数据源：

- 用户手动导出（App 内分享作品链接，或录屏）

```
关注 6  粉丝 251  获赞 892
```

### 作品列表为空 ⚠️

正确的作品列表接口是 **`/rest/v/profile/feed`**（不是 photolist），实测响应：

```json
{"result": 1, "pcursor": "1.787660131573E12", "feeds": [], "webPageArea": "profilexxnull"}
```

`result: 1` 表示**请求成功**，但 `feeds` 是空数组；页面同时显示「作品 收藏 **没有更多了**」，DOM 中作品卡片数 = 0，且**没有**私密锁图标或"仅粉丝可见"提示。

结论：**该账号在快手 Web 端不存在任何可访问的作品**。这不是抓取失败，也不是登录问题——接口正常返回了空结果。

推断（按可能性排序）：
1. 作品已全部设为私密 / 已删除下架
2. 作品仅在 App 端可见，Web 端不分发

> 注意：`/rest/v/profile/get` 返回的是**当前登录账号**（喵个咪喵 / userId 4393886674）的资料，不是目标账号——该接口在未显式传 userId 时返回自身。
