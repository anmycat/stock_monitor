## 1. AI 主力模型切换：云知声 U2-flash

### 1.1 用户给的参数

- 模型：`U2-flash`（OpenAI 兼容）
- api：`tp-` 开头 51 字符（**绝不入库**，只写 gitignored 的 `.env`）
- 地址：`https://maas-api.unisound.com/v1`（与代码既有 `UNISOUND_BASE_URL` 默认值一致）

### 1.2 改了什么

| 位置 | 改动 |
|---|---|
| 本地根 `.env`（gitignored） | 新增 `UNISOUND_API_KEY` / `UNISOUND_BASE_URL` / `UNISOUND_MODEL=u2-flash` / `UNISOUND_MAX_TOKENS=6000`。**根因**：pydantic-settings 从**当前工作目录**读 `.env`，本地 `quant_engine/.env` 从来没被加载过；ECS 用部署根 `/stock_monitor/.env`，本地补根 `.env` 才与生产布局一致 |
| `quant_engine/.env`（gitignored） | 同步写入同样 4 项（兼容从 quant_engine 目录启动的场景） |
| `config.py` | `UNISOUND_MODEL` 默认 `"u2"` → `"u2-flash"`：此前写 u2 由服务端隐式路由到 u2-flash、响应回显 u2-flash，请求/回显不一致；显式写出便于日志与健康面板核对 |
| `ai_summary.py` | 模型注册 `or "u2"` 兜底 → `or "u2-flash"`；订正过时注释（「项目用 u2 + 1500」→「u2-flash + 6000」） |
| `.env.example` | `UNISOUND_MODEL=u2-flash`、key 注释补 `tp-` 前缀说明 |
| `research/scripts/scan_secrets.py` | 新增 `tp-[A-Za-z0-9]{32,}` 识别（此前只认 `sk-`/`bs-` 等，`tp-` 密钥会漏检）；`test_secret_scan.py` 加回归 |
| `docs/38` A1 表 | ECS 部署必改项补 `UNISOUND_API_KEY`（新 key）+ `UNISOUND_MODEL=u2-flash`；E 执行顺序同步 |

### 1.3 实证（真实调用，非 mock）

```
POST https://maas-api.unisound.com/v1/chat/completions
model=u2-flash, max_tokens=300, "只回复两个字：正常"
→ HTTP 200 | 回显 model: u2-flash | finish_reason: stop | content: '正常'
→ usage: prompt=60 completion=21 (reasoning_tokens=21) total=81
```

本地运行时确认：`primary_model=unisound`、`model_id=u2-flash`、
`api_url=https://maas-api.unisound.com/v1/chat/completions`、weight=0.7、
max_tokens=6000。key 有效、模型名正确、端点可用。

> 注意：`completion_tokens=21` 全是 `reasoning_tokens`（思考型模型），正文「正常」
> 仅 2 字——印证 `UNISOUND_MAX_TOKENS` 必须给足（D69 已从 2500 升到 6000），
> 部署时 ECS `.env` 的显式 2500 **必须同步改成 6000**，否则空响应依旧。

## 2. D70 五条优化（全部零信号影响）

改造纪律：**只写展示层/旁路 attrs，不改 Signal 决策字段，不参与评分/风控/Kelly/回测**。
趋势信号零漂移铁律不变。

### N-08 非有限数入口拦截

- 新增 `quant_engine/utils/numeric.py`：`finite_or_none` / `sanitize_floats`，
  NaN/±Inf（含 numpy 浮点）→ None，合法值原样返回。
- `signal_to_api_dict()` 的 10 个浮点字段统一过清洗——这是 API 展示的 choke
  point。此前 NaN 会序列化成非法 JSON（`NaN`），前端 `JSON.parse` 抛错。
- 零信号影响：只作用序列化前的展示 dict，Signal 决策字段不动。

### N-02 行情质量元数据四元组（DSA `UnifiedRealtimeQuote` 范式）

- `_save_snapshot()` 增加 `source_name` 参数，快照记录来源源名。
- `_load_stale_snapshot()` 补齐 `df.attrs`：`quote_date`（归属日）/
  `provider_timestamp`（采集时刻）/`fallback_from`（原产出源）/
  `stale_seconds`（陈旧时长）/`data_quality='stale'` / `missing_fields`。
- 目的：docs/37 发现的 2.7~4.4h 陈旧报价现在可解释「谁的时间 / 哪个源 / 有多旧」。
- **只写 `df.attrs`，不改列不改值** → 趋势信号零漂移。

### N-03 源熔断增强（保守旁路版）

- `SourceStatus` 新增 `error_kind_counts`（timeout/error/empty_threshold 分类累计）
  与 `endpoint_cooldowns`（端点级冷却登记，避免一个端点 403 拉黑整源）。
- `record_error()` 分类计数、`reset()` 清空、`get_status_report()` 暴露。
- **未改** `is_available()` 的现有熔断判定 → 零行为变化、零信号影响。
- 说明：DSA 的 HALF_OPEN 半开探测状态机改动较大且会改变取数恢复时机，
  本批只交付「错误分类 + 端点级登记」的观测能力，半开探测留待单独裁定。

### N-04 自检端点 `GET /api/system/doctor`

- 加在 `system.py`，依赖 `verify_api_key`（与 API_AUTH_TOKEN 同批启用）。
- 聚合健康（Redis 连通）/ 数据源能力（复用 I-02 报告）/ 关键开关 /
  AI 主力模型标识。**脱敏**：只报 `api_auth_enabled` 布尔、`unisound_key_configured`
  布尔，**不输出任何 key/token/webhook**。
- 纯只读：不取数、不改状态、不参与信号。路由数 42 → 43。

### N-05 通知按通道字节预算（DSA 连修 4 例 flood-control）

- `manager.send()` 统一出口按渠道名查 `_CHANNEL_BYTE_BUDGET`（默认 4096 字节），
  `clip_to_byte_budget()` 按 UTF-8 **字符边界**截断，绝不切出半个汉字，
  截断追加 `…（内容过长已截断）`。budget<=0 不限制（测试/特殊场景）。
- 此前长中文日报可能超 webhook 上限导致整条发送失败；现在截断保主体。
- 只影响发送内容长度，不改信号/决策/节流计数。
