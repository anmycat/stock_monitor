## 二、回归方法与判据

### 2.1 双跑架构（worktree 对照）

| 跑次 | 代码 | worktree | 产出 |
|---|---|---|---|
| 重构后 | HEAD `d6e3ded3`（P5-f 后） | 主仓库 | `/tmp/sig_after.json` |
| 重构前 | `91162c76`（重构设计落库点） | `/tmp/pre_refactor` | `/tmp/sig_before2.json` |

两次运行**同一份静态数据、同一套 mock、同一扫描序列**，仅代码不同。若重构引入行为变更，信号集/字段必现系统性漂移；观测结果为零差异（§3）。

### 2.2 mock 中和清单（前后一致，保对比有效）

| 中和项 | 方法 | 理由 |
|---|---|---|
| 日K数据 | `get_daily_data` 按 `state['date']` **截断**注入研究数据 | 防未来函数：T 日扫描只喂 ≤T 的K线 |
| 股票池 | `get_stock_list` 返回 27 只研究池 | 免打全市场列表网络 |
| 市场宽度 | `get_realtime_quote` 返回研究池 T 日涨跌统计 | 与 `MarketAnalyzer._calculate_breadth` 同口径 up/total，免全市场请求 |
| 分钟线 | `get_minute_data→None` | 中和 TDX 全池探活（本地无网关）；降级路径与生产"网关故障"同路径 |
| LLM 增强 | sys.modules 注入假 `LLMRanker`/`CandidateContext`（透传） | 等价"LLM 不可用"原生降级；避免 3483 次真实 API 调用 |
| 通知 | `notifier.send_signal` 只记录 | 钉钉 webhook 未配置时本就降级 |
| cooldown | RedisCache 无 Redis 优雅降级 | 同序列前后一致 |

### 2.3 途中捕获：旧代码 fake 增强器首轮失效（设施问题，非代码缺陷）

首轮旧代码跑批（`sig_before.json`）完成后对比发现异常分布，甄别根因：重构前 funnel import 路径为 `quant_engine.services.llm_ranker`（扁平结构），而 mock 键名写在 `quant_engine.services.signals.llm_rananker`（重构后子包路径）——**旧代码的假增强器未生效**，走了真实 LLM/上下文层。修复：`_install_fake_enhancers()` 增加双路径兼容（新旧四种模块键全覆盖），重跑旧代码得 `sig_before2.json`。教训：mock 注入验证不能只跑新代码——**必须确认 mock 在旧代码侧同样生效**（本次靠字段分布异常抓获）。
