## B. P0 安全收口（需用户明确选择，本次未执行）

### B1. 推荐先做：安全组白名单（零代码风险，可随时回滚）

- 在云控制台把 ECS 的 **8000 端口**来源从 `0.0.0.0/0` 收窄为白名单 IP（办公出口 / 跳板机）；
- 22 端口 SSH 也建议一并收窄；
- 验证：白名单外 IP 应连不上 8000；白名单内 `/api/health` 仍 200。
- 回滚：控制台删规则即可。

### B2. 再做：启用 API_AUTH_TOKEN（前后端已就绪，需同批）

- 生成强随机 token：`python3 -c "import secrets; print(secrets.token_urlsafe(32))"`；
- 写入 `/stock_monitor/.env`：`API_AUTH_TOKEN=<生成的token>`；
- 重启三服务；
- **必须同步通知 UX 使用者**：首次打开页面会弹窗要求输入 API Key（存浏览器 localStorage，
  键名 `sm_api_key`），输入同一 token 后页面 reload；否则所有 `/api/*` 会 401。
- WS 自动带 `?token=`，无需额外配置。
- 回滚：清空 `.env` 的 `API_AUTH_TOKEN` 并重启 → 恢复匿名（不推荐长期）。

> 代码侧完备性已由 `test/test_api_auth_contract.py` 5 例静态护栏锁定：
> 后端 verify_api_key / verify_websocket_token、前端 X-API-Key 头 / WS token / 无裸 fetch。

## C. P2 运维加固（可延后，但建议同批做）

### C1. 加 swap（内存瓶颈缓冲）

- 当前：物理 1.6 GiB、Swap 0、三服务 MemoryMax 合计 1.5 GiB、RSS 合计 ~813 MB。
- 建议：`fallocate -l 512M /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile`，
  并在 `/etc/fstab` 加一行持久化。
- 风险：低；swap 只在内存吃紧时使用，不影响正常性能。

### C2. SQLite WAL 定期 checkpoint

- 当前：`history.db` 1.0 MB / `history.db-wal` 4.0 MB（WAL 是主库 4 倍）。
- 立即核查：备份脚本是否包含 `history.db-wal`；若只拷 `.db` 会丢最近交易数据。
- 建议：在 worker 空闲时段（如 23:00）加 cron：`sqlite3 /stock_monitor/data/history.db "PRAGMA wal_checkpoint(TRUNCATE);"`
  （ECS 若无 sqlite3 CLI，用 Python：`python3 -c "import sqlite3; sqlite3.connect('/stock_monitor/data/history.db').execute('PRAGMA wal_checkpoint(TRUNCATE)')"`）。
- 本次只读体检**没有执行 checkpoint**（写操作需用户确认）。

### C3. journald 日志限额

- 当前：归档+活跃 471.6 MB（含 11200 行幂等 DEBUG，代码侧已改为轮末汇总）。
- 建议：`/etc/systemd/journald.conf` 设 `SystemMaxUse=200M`，`systemctl restart systemd-journald`。
- 代码侧日志汇总生效后，新增量会大幅下降；此步是限制历史存档。
