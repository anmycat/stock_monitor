# 48 · Rust 重构深化方案：热点实测与边界（D79，2026-11-24）

## 1. 用户课题

「考虑用 Rust 重新编码提升项目」——承接 docs/25 §8.5/§8.6 的结论（AI coding 前提下从"明确否决"修正为"可行但当前不划算"），本轮做**深化 Rust 化**的具体路径评估：哪些模块值得继续下沉，边界在哪。

## 2. 实测热点（不是凭印象）

cProfile 环境：本地 venv py3.9 + pandas 2.2，`calculate_indicators()` 100 次循环，240 根 K 线 × 全字段：

| 函数 | 累计耗时(100次) | 占比 | 性质 |
|---|---|---|---|
| `calculate_indicators` 全链路 | 1.553s | 100% | — |
| `_advanced_features` | 0.754s | 48.6% | 十几处 `rolling().mean/max/std/concat` **已是 pandas C 级向量化** |
| `wilder_rsi` | 0.430s | 27.7% | 其中 `_load` 首次导入占 0.419s，**稳态 ≈0.1ms/次** |
| 其余 MA/MACD/KDJ/ATR/布林/OBV | ~0.37s | 23.7% | 全部 pandas/numpy 向量化 |

**关键发现**：
1. D78 已把 4 个 Python 级逐元素循环（wild_smooth / wilder_rsi / consolidation_days / consecutive_direction）全部下沉，**剩余代码里已无显著 Python 循环热点**。
2. `_advanced_features` 的 48.6% 不是"Python 慢"，是 pandas rolling 的固有开销；用 Rust 重写这些 rolling 需自研数值内核，收益上限是把 15ms → 假设 5ms/票（27 票 ≈0.27s/轮），但引入逐位等价风险（docs/25 §8.5.3 已实证 3 个位级坑）。
3. 全链路单次 11~15ms；扫描 27 票 ≈0.3~0.4s，而每轮 90%+ 耗时在 HTTP/LLM 外部等待（docs/25 §2）——即便计算归零，端到端提速 <5%。

## 3. 深化路径评估（按 ROI 排序）

| 候选 | 可行性 | 收益 | 风险 | 裁定 |
|---|---|---|---|---|
| A. 扩大 qerust：把 OBV/布林/ATR 等 rolling 下沉 | 技术上可做（Rust rolling mean/std 简单），但要复刻 pandas 的 `std(ddof=1)`、`min_periods`、NaN 传播语义 | 稳态每票省约 1~3ms；端到端 <1% | 逐位等价风险高（f64 求和顺序、ddof），D41 门禁需重建；pandas 语义细节多 | **暂缓**——收益不覆盖验证成本 |
| B. 批量化：把「整帧 27 票 × 全指标」一次性传进 Rust 算完 | 需把 pandas DataFrame 转 Arrow/数组，跨语言拷贝成本可能吃掉收益 | 理论省 Python↔Rust 往返 27 次（每次 µs 级） | 改动面大（改 API 契约/调用点） | **暂缓**——收益 µs 级，不值得 |
| C. 协议层深化（eltdx 已做） | 已落地：eltdx Rust TCP 协议核 6× 于 HTTP（docs/25 §8.1） | 已兑现 | — | **已做，保持** |
| D. 全量重写 | 24,131 行 / 44 模块 pandas / hmmlearn 生态断层 | 端到端 <5%（I/O 瓶颈） | 人月级 + 逐位等价 + 门禁重建 | **否决**（§8.5/§8.6 结论不变） |
| E. 保持现状 + 低风险增量：只在出现**新的 Python 循环热点**时按 D78 模式下沉 | 已建立构建/缓存/降级链路（D79 产物缓存秒级） | 按需 | 每次下沉配 11+ 位级测试 + D41 双跑 | **采纳为持续策略** |

## 4. 结论与方法

- **不启动新一轮 Rust 重写**：实测证明剩余热点是 pandas 向量化而非 Python 循环；D78 已把可下沉的循环下沉完。
- **保留并强化已建成的 Rust 层**：D79 产物缓存使部署从 2m27s → 秒级；`RUST_ACCEL_ENABLED=false` 可随时 A/B/回退。
- **触发新下沉的条件**（满足才立项）：
  1. cProfile 显示某个 Python 级循环累计占比 >10% 且稳态（非首次导入）；
  2. 该循环有确定性的数值语义（可写位级等价测试）；
  3. 下沉后端到端收益可测（不只微基准）。
- **不做的事**：不为"用 Rust"而重写 pandas 向量化路径；不碰策略语义（保持 Python）；不让 Rust 参与任何 df 列/值修改（趋势类除外铁律）。
