## 2. 核查发现的 4 个真实缺口

### 2.1 三招主体确实在，且 D66 新路径没破坏它

`data/sources/eastmoney.py` 已有 `_Throttle`（`MIN_INTERVAL=1.0` + `JITTER_RANGE=(0.15, 0.6)`）、模块级 `_SESSION = requests.Session()`、统一入口 `_get()`。核查确认：

- `get_all_stocks` / `get_realtime_quote` / `get_capital_flow` / **`get_daily_data`（D66 新增 push2his 日K）** 全部经 `_get_json()` → `_get()`；
- `em_pool.py`（push2ex 涨停池）显式复用 `EastMoneySource._get_json`；
- D66 `daily_guard.cross_check()` 调用 `EastMoneySource.get_daily_data` → 同样走限速链。

**即：D66/D67 新增的东财调用没有绕过三招。** 这一点先排除，避免误修。

### 2.2 缺口 A（最严重）：三服务各自为政，进程间限速不成立

现网是 `quant-api` / `quant-worker` / `quant-beat` **三个独立 systemd 进程**。`_THROTTLE` 与 `_SESSION` 都是模块级对象，每进程各持一份 → 三个进程可同时向东财发请求，实际 QPS 可达单进程的 3 倍。截图要求「两次请求至少隔一秒」在**全局**层面并未成立，这是「避免被封」的实质风险。

### 2.3 缺口 B/C/D：三处东财域请求完全绕过三招

| 位置 | 域名 | 原实现 | 问题 |
|---|---|---|---|
| `data/sources/news_sources.py::EastMoneyNewsSource` | `np-weblist.eastmoney.com` | `urllib.request.urlopen` 直连 | 每次新建连接；3 个栏目串行无间隔、无抖动 |
| `services/monitors/news_service.py::_search_eastmoney_keyword` | `search-api-web.eastmoney.com` | `with httpx.Client(...)` | 每次新建连接池；零限速 |
| `data/sources/fund_holdings.py` | `fundf10.eastmoney.com` | 自建 `requests.Session()` + 年份循环 `sleep(0.3)` | 独立连接、0.3s 远低于「≥1s」、重试间无限速 |

这些虽是新闻/基金档案域而非行情域，但**同属东财 IP 风控视野**，绕过即等于三招形同虚设。

## 3. 修复方案

### 3.1 Redis 预约式跨进程全局限速（缺口 A）

`_Throttle` 增加可选的 Redis 客户端（由装配点注入，**绝不自建连接池**），用一段 Lua 原子脚本预约「下一个允许时刻」：

```lua
local now = tonumber(ARGV[1])
local gap = tonumber(ARGV[2])            -- MIN_INTERVAL + jitter
local last = tonumber(redis.call('GET', KEYS[1]) or '0')
local allowed = now
if last + gap > allowed then allowed = last + gap end
redis.call('SET', KEYS[1], string.format('%.6f', allowed), 'EX', 120)
return allowed - now                    -- 本进程需 sleep 的秒数
```

- 键 `em:throttle:next_allowed`（TTL 120s），三服务共享 → **全局任意两次东财请求间隔 ≥1s + 抖动**；
- 客户端时间即可（三服务在同一台机器，时钟一致）；
- 排队上限 10s（三服务最坏约 3×1.6s），超限告警并截断，避免 worker 卡死；
- 抖动在**预约时**计算，节奏仍不可预测，满足第②招。

**四级优雅降级**（任何一级失败都退回 D53 原行为，零行为变化）：

1. `EM_GLOBAL_THROTTLE=False` → 纯进程内锁；
2. `attach_global_throttle()` 只在 `cache.is_connected=True` 时注入 → 本地无 Redis 时**不产生任何 socket 探测开销**；
3. Redis `eval` 异常 → 30s 节流告警 + 降级进程内锁，绝不阻断行情请求；
4. `guarded_fetch` 用 `fork`，子进程继承父进程 Redis 连接池不安全 → 用 `os.getpid()` 检测，pid 变化即丢弃继承的 client，降级进程内锁。

### 3.2 唯一入口 `em_get()`（缺口 B/C/D）

新增模块级 `em_get(url, *, params, headers, timeout)`：**所有 `eastmoney.com` 子域请求的唯一出口**——`_THROTTLE.wait()` + 共享 `_SESSION.get()` + 按请求合并 headers（不同子域 Referer/UA 不同，不污染共享 Session）。

- `EastMoneySource._get()` 改为委托 `em_get()`，保留旧签名，杜绝第二条旁路；
- 东财快讯：`_em_get_with_retry()` 走 `em_get`，保留 2 次重试语义（每次重试重新预约限速），`raw_fetcher` 测试注入点不变；
- 个股新闻搜索：去掉 `with httpx.Client`，改 `em_get`；
- 天天基金：删掉自建 Session，两个请求点改 `em_get`，移除 0.3s 弱限流；
- `em_pool` 与 D66 日K/复核链路本就走 `_get_json`，自动继承。

**技术边界（如实说明）**：第③招「所有请求共用一个连接」在**进程内**由 `_SESSION`（keep-alive）完整满足；跨进程无法共享 TCP 连接（OS 层限制，强行共享会破坏连接池语义），因此用 Redis 全局限速补足「避免被封」的实质目标。三服务是三个进程、三份连接池，但**共享同一条限速时间线**。

### 3.3 配置与装配

- `config.py` 新增 `EM_GLOBAL_THROTTLE: bool = True`，`.env` 设 `false` 即回退 D53 口径；
- `MarketDataRepository.__init__` 在 `source_manager.attach_cache(self.cache)` 之后调用 `attach_global_throttle(self.cache)`，复用同一个已连接的 `RedisCache`，不新建连接池；
- 新增 Redis 键：`em:throttle:next_allowed`（TTL 120s）。

## 5. 过程教训（重要）

本轮清理 lint 时误用 `ruff check quant_engine --select RUF100 --fix`：`--select` 覆盖了项目 `pyproject.toml` 的规则集，导致**全仓 131 处 `noqa` 被判为「unused」并批量删除**，其中大量是 `per-file-ignores` 下 BLE001 的**精确豁免**——这正是项目长期记忆里记录过的坑。

处置：先 `git diff` 备份到 `/tmp/d68_ruff_accident_backup.patch`，再用脚本从 HEAD 逐行还原 noqa 注释（只补注释、不动代码），对 14 个非本轮文件 `git restore` 精确回滚，对 `market_data.py` 回滚后重新应用本轮 8 行改动。最终 `git status` 只剩本轮 6 个文件、ruff 全绿、无控制字符污染。

**纪律固化**：本项目**禁止**对 `quant_engine/` 使用带 `--select` 的全仓 `--fix`；新增 `noqa` 后只针对**具体文件**跑 `ruff check <file>` 确认，不要批量修。

## 6. 诚实边界与遗留

1. **部署状态见 §8**。跨进程全局限速只有在三服务重启、且 Redis 已连接时才真正生效；本地无 Redis 时保持 D53 单进程限速，**功能完全等价**。部署后需实测 `em:throttle:next_allowed` 键与三服务日志，才能确认全局预约真正工作（本地无 Redis，专项测试只验证了逻辑与降级，未验证 ECS 实盘）。
2. 新闻 / 基金档案域请求不属「行情服务器」，仍按 worker 既有调度（早报 9:15、盘后 ETF 监控）与 API 个股查询触发；本轮**未新增时段硬门控**，避免打断盘后查询功能。截图第 2 条的行情静默由 D53/D58 继续保证。
3. `_http_get`（`news_sources.py` 通用函数）仍用 `urllib`，但只服务同花顺 / 新浪 / RSS 等非东财域；若日后把 RSS 配置指向东财域，需改走 `em_get`（静态护栏测试已覆盖 `sources/` 目录的直连检查）。
4. 截图第 3、4、6、7、8 条属策略/调研排期，未在本轮推进；第 6 条的 TDX 分支已由 D67 I-03 给出「上游停供、不换库」的实测结论。
5. **零信号影响**：改动全部在网络请求层（限速与连接复用），不改任何返回数据结构、不改评分/风控/Kelly/回测口径；D41 双跑用于实证。
6. 可回退：`.env` 设 `EM_GLOBAL_THROTTLE=false` → 回到 D53 纯进程内三招；`em_get` 统一入口本身无开关（它是反封禁的强制性约束，不宜允许绕过）。
