# 03 · 数据模型

> 版本：v1.0 · 2026-10-15
> 上游依赖：02（数据源）、docs/12 §6-7（Signal 契约与执行闭环）、docs/14（半年验证字段）
> 本文定义 SQLite 库表结构、Signal 契约、持仓状态机与成交回报协议。**规则引擎只认本模型的字段名，改名=改契约，必须同步 rules/ 与 scripts/。**

---

## 1. 存储选型：SQLite 单文件

| 决策 | 理由 |
|---|---|
| SQLite（非 MySQL/PostgreSQL） | 单文件、零运维、与 FC/ECS 均可打包带走；每日 dump 到 OSS 即备份 |
| WAL 模式 | 读写不互斥，盘中预警（Phase 3）与收盘计算可并行 |
| 不用 ORM | 建表 SQL 内嵌 `scripts/db_init.py`，原生 sqlite3，依赖为零 |

库文件：`data/stock.db`（gitignore，仅 OSS 备份进版本）。

## 2. 表结构

### 2.1 klines — 日K缓存（数据层唯一事实源）

```sql
CREATE TABLE klines (
    code TEXT NOT NULL,            -- '300308.SZ'
    date TEXT NOT NULL,            -- 'YYYY-MM-DD'
    o REAL, h REAL, l REAL, c REAL,
    prev REAL,                     -- 前收盘（不复权）
    pct REAL,                      -- 涨跌幅%
    amp REAL,                      -- 振幅%
    vol REAL,                      -- 成交量（手）
    amount REAL,                   -- 成交额（元）
    turn REAL,                     -- 换手率%
    source TEXT,                   -- eastmoney/sina/tencent/cache
    suspect INTEGER DEFAULT 0,     -- 数据质量闸门标记（见02 §5）
    fetched_at TEXT,
    PRIMARY KEY (code, date)
);
CREATE INDEX idx_klines_date ON klines(date);
```

- 只存不复权；指标一律不落库（每次从本表现算，保证"当日可知"可复现）
- `suspect=1` 的记录：信号引擎跳过并在周报中列出

### 2.2 signals — 信号表（T 日生成，全生命周期可追溯）

```sql
CREATE TABLE signals (
    signal_id TEXT PRIMARY KEY,    -- S-YYYYMMDD-<code>-<rule>
    signal_date TEXT NOT NULL,     -- T 日（信号生成日）
    code TEXT NOT NULL,
    name TEXT,
    direction TEXT,                -- long
    rule TEXT NOT NULL,            -- R01..R13/C01..C05（规则ID，非键名）
    rule_name TEXT,
    rating TEXT,                   -- A/B/C/D（UZI-Skill 四级校准，见04）
    confidence TEXT,               -- high/medium/low
    capital_tag TEXT,              -- SC-01/HC-01/YZ-01/DR-01
    regime TEXT,                   -- bull/neutral/bear（R13 输出）
    entry_low REAL, entry_high REAL,
    stop_loss REAL, take_profit REAL,
    position_pct REAL,             -- Kelly 输出，百分数，0<position≤25
    reason TEXT,
    executable INTEGER,            -- T+1 开盘校验结论 0/1
    exec_note TEXT,                -- '开盘涨停'/'除权跳空'等
    sim_pnl_pct REAL,              -- 按信号价模拟成交的盈亏%（回测口径）
    created_at TEXT,
    UNIQUE (signal_date, code, rule)   -- 幂等：同日重跑只更新
);
CREATE INDEX idx_signals_date ON signals(signal_date);
```

### 2.3 positions — 持仓状态机（无券商接入的核心）

```sql
CREATE TABLE positions (
    pos_id INTEGER PRIMARY KEY AUTOINCREMENT,
    signal_id TEXT REFERENCES signals(signal_id),
    code TEXT NOT NULL,
    name TEXT,
    state TEXT NOT NULL,           -- PENDING / OPEN / CLOSED / CANCELLED
    open_date TEXT,                -- T+1
    open_price REAL,               -- 回报价；未回报=区间中值（模拟成交）
    shares INTEGER,
    is_sim INTEGER DEFAULT 1,      -- 1=模拟成交 0=真实回报
    close_date TEXT,
    close_price REAL,
    close_reason TEXT,             -- 止损/目标/倒T接回/派发离场/人工
    pnl_pct REAL,                  -- 不复权口径
    updated_at TEXT
);
CREATE INDEX idx_positions_state ON positions(state, code);
```

状态流转（docs/12 §7.2）：

```
PENDING ──成交回报/模拟成交──→ OPEN ──卖出/止损/目标──→ CLOSED
   │                            │
   └──开盘作废(一字板/跌停)──→ CANCELLED
```

- `OPEN` 持仓每日 15:30 重算一次：DR-01 派发→减仓建议；R06 倒T→做T建议；R10 冻结→停开新仓
- 止损/目标按**日K收盘价**判定（与纪律一致，不用盘中价）

### 2.4 events — 事件日志（可观测性）

```sql
CREATE TABLE events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ts TEXT NOT NULL,
    level TEXT,                    -- info/warn/error
    kind TEXT,                     -- signal_generated/pushed/fill_report/fetch_fail/risk_freeze
    ref_id TEXT,                   -- signal_id / pos_id
    detail TEXT                    -- JSON 字符串
);
```

周报、健康检查、失败告警全部查此表。

### 2.5 config_snapshot — 配置快照（复现性）

```sql
CREATE TABLE config_snapshot (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ts TEXT,
    rules_version TEXT,            -- methodology_rules.json 的 _meta.version
    rules_hash TEXT,               -- 规则库内容 hash
    adopted_config TEXT            -- 当日生效的采纳配置 JSON（R13阈值等）
);
```

**每次信号生成前落一条快照**——半年后复盘"当时为什么出这个信号"时，规则库可能已改，快照是唯一答案。

## 3. Signal 契约（引擎→推送的唯一出口）

```json
{
  "signal_id": "S-20261014-300308-R01",
  "code": "300308.SZ", "name": "中际旭创",
  "direction": "long", "rule": "R01", "rule_name": "动量突破买入",
  "rating": "B", "confidence": "high",
  "capital_tag": "HC-01", "regime": "neutral",
  "signal_date": "2026-10-14",
  "entry_range": [10.20, 10.50],
  "stop_loss": 9.80, "take_profit": 11.50,
  "position_pct": 15.0,
  "reason": "连涨2日+量比1.8+突破20日高点",
  "executable": true, "exec_note": ""
}
```

字段口径：`position_pct` 为**百分数**（15.0 即 15%，Kelly 单位统一，docs/11 踩过小数/百分数混用的坑）；`entry_range` 为 T+1 开盘可接受区间；`rating` 四级校准见 04 因子研究规范 §5。

## 4. 成交回报协议（人工执行回写）

用户回复文本 → 解析 → positions 表：

```
B 300308 10.35 5000      # 买入：方向 代码 成交价 股数
S 300308 11.80 5000      # 卖出
```

- 解析容错：全角/半角、空格/逗号分隔、代码带不带 `.SZ` 均可
- **未回报**：按 `entry_range` 中值记模拟成交（`is_sim=1`），持仓跟踪照常，卡片标 `模拟持仓`
- 回报纠正：同方向同代码再次回复覆盖上次
- 回报超时：T+3 仍未回报的 PENDING 自动转 CANCELLED 并在周报统计"人工执行率"

## 5. 与规则库的映射关系

| 规则库键 | 本模型落点 |
|---|---|
| R01-R06（交易规则） | signals.rule / entry_range / stop_loss / take_profit |
| R07-R10（风控） | events(kind=risk_freeze) + positions 状态流转 |
| R11 市赚率 | 选股层：PR>0.8/亏损股的代码不进 signals（负面清单，见05 §4） |
| R12 预期差 | **默认关闭**（docs/14 半年证伪其环境依赖性，见05 §4） |
| R13 牛熊 | signals.regime + "指数 bias20≤-2% 禁 R05"变体（V7 采纳配置） |
| C01-C05（筹码） | C01 选股参考进 reason；C02 仅观察不进 signals；C03/C04 禁买过滤 |
| kelly 参数 | signals.position_pct |

> 规则库 `methodology_rules.json` 是配置的唯一事实源；本模型是运行时状态的唯一事实源。二者通过 `config_snapshot` 关联。
