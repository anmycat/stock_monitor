## 7. 提升与融合战略规划（2026-10-20，全文见 research/docs/19）

**输入**：当日三份调研（全链审计 D26 / ECS 性能与架构 / DSA 项目分析，归档 research/docs/16-18）+ 项目记忆。**融合总原则：抄工程范式与规则化设计，不抄 LLM 依赖与市场广度**——守住"ECS 常驻实时性 + 数据守护"主场。

```
第一层 修命（本周）      让系统"配得上"谈提升——数据链路+部署+防护
        ↓ 前置依赖：不修则后面全白搭
第二层 补骨（2-3 周）    吸收 DSA 的告警/舆情范式——规则化+质量分级
        ↓
第三层 增肌（1-2 月）    深化主场优势——DSA 物理上做不到的实时性与数据守护
```

### 7.3 第三层：增肌（A1-A4，主场深化）

| # | 事项 | 为什么 DSA 做不到 |
|---|---|---|
| A1 | 盘中实时性深化：burst 快照 300s → 60s；活跃池竞价期可刷新 | Actions 定时物理上做不到分钟级常驻 |
| A2 | CodeGuard 扩展：代码一致性 → 数据一致性（涨跌幅停板校验：非 ST ±10%/创业科创 ±20%/北交所 ±30%） | DSA 无数据守护概念 |
| A3 | ETF 持仓 × 异动联动：成分股 burst 告警附所属 ETF 及持仓权重变化 | DSA 无 ETF 持仓监控 |
| A4 | 信号后验 T+N 闭环：信号 → T+N 实际走势 → 命中率统计 → 反哺参数 | DSA 的报告不产生可验证的信号记录 |
