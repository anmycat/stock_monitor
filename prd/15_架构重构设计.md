## 1. 背景：为什么重构

### 1.1 重构动因（审计实证，非臆测）

2026-10-22 对 quant_engine 85 个 Python 文件（16,146 行）做了全量架构审计，实测结论：

| # | 问题 | 实测证据 | 严重度 |
|---|---|---|---|
| A1 | **DataCenter 上帝对象** | `data/datacenter.py` 混合 4 种职责（取数编排/缓存读写/数据校验/市场概览），**15 个模块直接依赖它**（api.dependencies、beat、worker、backtest×2、services×11） | P0 |
| A2 | **routes.py 单文件上帝路由** | 1,122 行 / 36 端点 / 20 个域 / 37 个顶层函数，无按域拆分 | P1 |
| A3 | **services 包 30 模块扁平化** | `signal_generator` 是内部枢纽（6 个包内依赖）；`code_guard → etf_monitor` 等跨界依赖方向可疑；监控/信号/风控/通知/AI 五族混居 | P1 |
| A4 | **死代码** | `correlation_manager.py` 384 行**零调用**（`get_correlation_manager` 无任何消费方）；akshare 遗留链半死（`akshare_source` 被 source.py 注册 + hot_money_monitor 使用，但 akshare 未安装，PRD 14 §388 记载 ETF 监控已弃用） | P2 |
| A5 | **质量债** | F/E9 真问题 73 项（61 未用导入 + 6 未用变量 + 4 空 f-string）；BLE001 盲 except 172 处；风格现代化 ~1,205 项；函数内延迟导入 17 处（部分掩盖耦合） | P2-P3 |

### 1.2 必须保护的资产（重构的约束条件）

审计同样确认了现状的**健康部分**，重构不得破坏：

1. **模块级零循环依赖**（Tarjan SCC 实测全部 size 1）——这是最大的既有资产，新架构必须维持
2. data 包内部结构清晰（datacenter → cache/source → sources 链干净）
3. notifiers 家族结构良好（base + 4 渠道实现 + manager）
4. DI  wiring 集中于 `api/dependencies.py`（FastAPI 惯例，保留）
5. 测试基线 **172/172 全绿** + 导入冒烟 + API 冒烟 4 端点 200
6. 生产运行中：ECS 8.134.89.55:8000，quant-api/quant-worker/quant-beat 三 systemd 服务，一键部署 `deploy/deploy_onekey.sh`

### 1.3 重构目标（可检验）

- G1：消灭 P0/P1 结构问题（DataCenter 拆分、routes 按域拆分、services 分族）
- G2：死代码清零（correlation_manager、akshare 链）
- G3：F/E9 73 项清零；BLE001 172 处完成分级处置（保留必要宽捕获 + 收窄其余）
- G4：**行为零变更**——每阶段 172 测试 + API 冒烟全绿才算完成；API 响应结构不变（前端 UX/ 不变）
- G5：维持模块级零环 + 新增依赖宪法（机器可检：每阶段跑依赖图审计）
- G6：research/ 线脚本对 quant_engine 的引用同步更新（cross_check 等 3 个脚本）

## 2. 目标架构

### 2.1 分层宪法（依赖只准向下）

```
L0 入口/接口   main.py worker.py beat.py api/
                │  只准依赖 L1（经 dependencies.py 注入）
L1 服务层      services/{monitors,signals,risk,notifications,ai,market}/
                │  只准依赖 L2/L3/L4；子包间依赖见 §2.3 有向图
L2 计算层      strategies/ backtest/
                │  只准依赖 L3/L4；backtest 禁止依赖 services（现状违规，本重构修复）
L3 数据层      data/{sources,repositories,cache,source,source_manager} models/
                │  只准依赖 L4 与同层
L4 工具层      utils/ config.py
                │  零内部依赖（config 可被全层依赖，视为基础设施不参与分层）
```

**机器可检**：每阶段结束重跑架构审计脚本（Tarjan SCC + 分层违规检测），结果记入阶段报告。新增依赖宪法违规 = 阶段不通过。

### 2.2 data 层重组（解决 A1：DataCenter 拆分）

现状 `DataCenter`（191 行，10 方法）四职责混合。拆分原则：**取数编排与缓存门面分离，校验归 utils**。

```
data/
├── cache.py                   # 不变（RedisCache，优雅降级已在）
├── source.py                  # 不变（CompositeSource 源注册；剔除 akshare 注册项）
├── source_manager.py          # 不变（容错调度）
├── sources/                   # 不变（纯源适配层；akshare_source.py 切除）
└── repositories/              # 【新】仓储门面层
    ├── __init__.py
    └── market_data.py         # MarketDataRepository：DataCenter 的取数+缓存编排职责
```

- `MarketDataRepository` 保留 DataCenter 全部公开方法签名（get_stock_list/get_daily_data/get_minute_data/get_realtime_quote/get_all_realtime_quotes/get_cached_quote/set_cached_quote/get_market_overview）——**调用方 15 个模块仅 import 路径与类名切换，用法零改动**
- `_validate_dataframe`（数据校验）移入 `utils/market_sanity.py`（B5 单一事实源，D32 已确立的方向）
- 内部 monolith 无外部消费者，直接迁移所有 import 不留垫片（见 §3.2）；research/ 线脚本引用在 P5 统一处理

### 2.3 services 分组（解决 A3）

按职责分 6 个子包 + 2 个顶层保留。子包间依赖必须成 DAG（实测现有边全部兼容）：

```
services/
├── __init__.py                # 聚合 re-export（保持 api/dependencies 现有 import 路径可用）
├── code_guard.py              # 保留顶层（E 线独立功能，定时巡检性质）
├── portfolio.py               # 保留顶层（组合层，被 routes 直接用）
├── monitors/                  # 监控族：只依赖 data/utils，禁止依赖其他子包
│   ├── etf_monitor.py
│   ├── etf_holdings_monitor.py
│   ├── sector_monitor.py
│   ├── hot_money_monitor.py
│   ├── burst_monitor.py
│   ├── news_monitor.py
│   └── news_service.py
├── market/                    # 市场分析族：只依赖 data/utils/models
│   ├── market_analyzer.py     # HMM
│   ├── market_alert.py
│   ├── hotspot.py
│   └── data_validator.py
├── risk/                      # 风控族：只依赖 data/utils/models
│   ├── risk.py
│   ├── position.py
│   ├── position_sizer.py
│   ├── stop_loss_manager.py
│   └── cooldown.py
├── signals/                   # 信号族：可依赖 market/risk/notifications（实测现有边）
│   ├── signal_generator.py
│   ├── signal_tracker.py
│   └── candidate_context.py
├── notifications/             # 通知族（原 notifiers/，零内部依赖）
│   ├── base.py manager.py feishu.py telegram.py wechat.py
└── ai/                        # AI 族：可依赖 market
    ├── ai_summary.py
    ├── llm_ranker.py
    └── agent_router.py
```

**现有包内边的映射**（全部保留，无新增）：

| 现有边 | 新位置 | 合法性 |
|---|---|---|
| signal_generator → cooldown/market_analyzer/notifiers/position/position_sizer/risk | signals → risk/notifications/market | ✅ signals 允许依赖三者 |
| etf_holdings_monitor → etf_monitor | monitors 包内 | ✅ 同族 |
| hotspot → sector_monitor | market → monitors | ⚠️ **market 依赖 monitors**——宪法修正：market 允许依赖 monitors（市场预警消费板块监控数据是业务必需），或 hotspot 移入 monitors。**裁定：hotspot.py 移入 monitors/**，market 族保持零子包依赖 |
| code_guard → etf_holdings_monitor/etf_monitor | 顶层 → monitors | ✅ 顶层可用所有 |
| llm_ranker → ai_summary | ai 包内 | ✅ 同族 |
| candidate_context → news_service | signals → monitors | ✅ signals 允许依赖 monitors |

**宪法最终版**：`monitors/market/risk/notifications` 四族零子包间依赖（叶族）；`signals → {monitors, market, risk, notifications}`；`ai → {monitors, market}`；`code_guard/portfolio` 顶层自由。这是 DAG，机器可检。

### 2.4 api 层拆分（解决 A2）

```
api/
├── dependencies.py            # 不变（DI 中心）
├── auth.py                    # 不变
├── websocket_enhanced.py      # 保留（WebSocket 单文件合理，721 行含优先级堆/连接管理）
└── routers/                   # 【新】按域路由（APIRouter 组合）
    ├── __init__.py            # 聚合 export_router()
    ├── market.py              # /api/market ×2
    ├── signals.py             # /api/signals ×2
    ├── portfolio.py           # /api/portfolio ×2
    ├── etf.py                 # /api/etf ×4
    ├── news.py                # /api/news ×3
    ├── sectors.py             # /api/sectors ×3
    ├── evaluation.py          # /api/evaluation ×3
    ├── system.py              # /api/system ×2 + /api/health
    ├── alerts.py              # /api/alerts ×2

    ├── summary.py             # /api/summary ×2
```

- **URL 全量不变**（36 个端点路径、方法、响应结构一一对应，前端零改动）
- `routes.py` 删除，`main.py` 改挂 `routers.export_router()` 组合

### 2.5 backtest 依赖净化（修复唯一分层违规）

现状 `backtest/engine.py → services`（L2→L1 反向）。处置：engine 需要的服务能力（signal_tracker 等）改**参数注入**——`api/routes/backtest` 与 `worker` 调用处传入实例，engine 模块本身只依赖 data/models/utils。`post_evaluation.py` 已部分如此，补齐 engine。

## 3. 迁移策略

### 3.1 总原则：阶段原子迁移 + git 即回滚

本项目是**内部 monolith**（quant_engine 无仓库外消费者；research/ 脚本引用同步改），因此不做长期兼容垫片——每阶段一次性完成"模块搬迁 + 全部 import 切换 + 测试通过"，一个 commit 一个阶段，部署脚本可独立发布任一阶段。回滚 = `git revert` 阶段 commit + 重新部署。

### 3.2 阶段计划（每阶段验收标准相同）

**每阶段通用验收**（缺一不可）：
1. 导入冒烟：`main/worker/beat` 三入口 import OK
2. 全量测试：172/172（随阶段扩充，只增不减）
3. API 冒烟：4 关键端点 200（/api/health /api/market /api/signals /api/evaluation/runs）
4. 架构审计：SCC 零环 + 分层违规零新增（脚本化，输出记入阶段报告）
5. ruff F/E9 计数不增（目标递减至 0）
6. git commit（message 注明阶段号 + 验收结果）

| 阶段 | 内容 | 预估改动量 | 特殊风险 |
|---|---|---|---|
| **P0 清基** | 切除 correlation_manager.py（384 行，零调用）；切除 akshare_source.py + source.py 注册项 + hot_money_monitor 改直连东财/腾讯；F/E9 73 项全清 | 中 | akshare 切除须确认 hot_money 降级路径可用（akshare 本就未安装，行为不变） |
| **P1 data 层** | DataCenter → repositories/market_data.py；`_validate_dataframe` → market_sanity；15 个调用方 import 切换；datacenter.py 删除 | 中 | 缓存 key/TTL 行为须逐一对齐 |
| **P2 services 分族** | 30 模块 → 6 子包（hotspot 移 monitors）；`__init__.py` 聚合保持 dependencies.py 现有 import 路径；全部内部 import 切换 | 大 | signal_generator 6 依赖边逐一验证；notifiers 家族整体搬迁 |
| **P3 api 拆分** | routes.py 1122 行 → 12 个域 router；URL/响应逐一对齐；main.py 挂载切换 | 大 | 36 端点逐一核对（路径/方法/响应模型）；前端 UX/ 零改动验证 |
| **P4 L2/L1 违宪边净化** | engine 去 services 依赖（参数注入）；funnel 去 llm_ranker/candidate_context（参数注入）；agent_router 去 signals（调用方注入扫描能力）；调用方（api routers/worker）适配 | 中 | 回测入口行为对齐（信号数/回测结果不变） || **P5 收尾** | BLE001 172 处分级处置（必要宽捕获保留+注释，其余收窄或改具体异常）；延迟导入 17 处评估收敛；风格现代化分批（UP006/UP045/I001 等机械项，ruff --fix 可批处理）；research/ 3 脚本 import 同步；prd/00 架构图重绘 + 12 审计清单 + README/manifest 升版 | 大 | 风格现代化改动面最大——拆独立 commit，可分批可回退 |

### 3.3 部署与生产协调

- 每阶段 commit 后由用户决定是否部署（部署需要 SSHPASS，不在自动流程内）
- 建议部署节奏：P0/P1 完成后部署一次（低风险验证管线），P2/P3 各部署一次，P5 分批部署
- 任何阶段部署后异常 → `git revert` + 重部署，回滚时间目标 <10 分钟
