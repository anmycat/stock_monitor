> 版本：v2.0（2026-10-16 模块化重组版）｜重组自：调研 system/02 + docs/15 免费行情接口调研报告（2026-10-15 实测）+ 产品数据层代码实证
> 本文定义系统吃什么数据、从哪来、口径是什么、挂了怎么办。**数据口径错误会让全部验证结论错位。**

## 1. 口径总原则：与回测完全一致

全部规则的验证基于**不复权日K**，指标由日K自算。任何数据源、任何加工环节偏离这个口径，信号即失效。

| 维度 | 规定 | 违反后果 |
|---|---|---|
| 复权 | 一律不复权 | 前复权会改写历史价格，MA/RSI/筹码分布全部偏移 |
| 频率 | 日K（实时路径为分钟级快照，仅用于盘中提醒，不产生回测口径信号） | 分钟K混入日K信号破坏"当日可知"纪律 |
| 指标来源 | 引擎自算（MA5/MA20/RSI/KDJ/量比/筹码） | 外部指标接口有陈旧快照风险（教训：neodata 估值快照 PE 错误） |
| 时区 | 东八区（Asia/Shanghai） | 跨日错位，信号日与成交日整体偏移一天 |

## 3. 行情接口实测调研结论（docs/15，2026-10-15，本机家庭宽带实测）

> 方法：实时实测（延迟/成功率/批量能力）+ 全网检索（官方文档 + 技术公众号）+ GitHub 项目健康度核查。生产环境（ECS）表现需以上线后复测为准。

### 3.1 实测结论总表

| 方案 | 注册 | 延迟 | 稳定性（实测） | 建议定位 |
|---|---|---|---|---|
| **腾讯 qt.gtimg.cn** | 免注册 | ~0.2s | **15/15 稳定**，支持 60 只/次批量 | **主力实时源** |
| **新浪 hq.sinajs.cn** | 免注册 | ~0.2s | **15/15 稳定**；分钟K 0.36-0.71s 可用 | **备源 1（实时）+ 分钟K 源** |

| **Tushare Pro** | **需注册**（送 100 积分 + 完善资料 20 = 120 积分） | HTTP 秒级 | 未实测（需 token） | **日K/历史数据主力（补偿源）** |

| 网易/和讯 | 免注册 | — | **已失效** | 放弃 |
| stooq | 免注册 | 慢 | 格式需修正 | 备选 |
| 雅虎财经 | 免注册 | — | 429 限流，A股支持差 | 放弃 |

### 3.2 东财封禁事件详解（重要风险发现）

- 首轮 3 家均 200 成功；连续 burst 后东财全部失败（0/15），表现为 TCP 层直接拒连（"Remote end closed connection without response"，非 HTTP 错误码）
- 暂停 65 秒后仍未恢复；更换域名（push2delay / 80.push2）同样被封
- **解读**：东财对突发流量极敏感，触发的是 **IP 级风控**而非频次软限制。全市场扫描类系统（pz=5000 + 循环刷新）极易踩雷

### 3.3 慢速接口的合理用法（对应"允许慢速接口"）

分钟K/日K等非实时路径不参与盘中决策，可用慢源 + 本地缓存，把慢源对系统的影响降到零。新浪分钟K 0.36-0.71s 实测可用，适合收盘后/低频路径。

### 3.4 注册制 API 标注（需要注册的均已注明）

### 3.5 Tushare Pro 应急源配置（2026-10-16 登记）

**定位原则：收费源，只做应急，不做主力。免费源（腾讯/新浪/东财/akshare）恢复正常后立即切回。**

| 项 | 值 |
|---|---|
| Token | 已配置于 `coding/quant_engine/.env` 的 `TUSHARE_TOKEN`（用户 2026-10-16 提供，全文见 .env，本文不复制明文） |
| MCP 服务 | `https://api.tushare.pro/mcp/?token=<token>`（模型上下文协议入口，供 AI 工具直连） |
| HTTP API | `https://api.tushare.pro`（POST，字段 `api_name`/`token`/`params`/`fields`） |
| 积分档位 | 120（注册 100 + 完善资料 20），恰好覆盖日线等基础行情接口 |

**切换纪律**：
1. 免费源全部不可用（腾讯/新浪/东财 burst 封禁 + akshare 同源失效）时，才允许切 Tushare
2. 切换是**手工操作**：代码中当前**没有 tushare 通路**（`data/sources/` 仅 eastmoney/tencent/sina 三源 + akshare_source，`TUSHARE_TOKEN` 在 Python 代码中零引用），实际启用前需先写 `TushareSource` 适配器（实现 `data/source.py` 的 Source 接口）并注册进 SourceManager
3. 免费源恢复后切回，并把 Tushare 调用量压到最低（积分即额度，burst 浪费）
4. `.env` 中 `DATA_SOURCE=tushare` 是**遗留字段**（config.py 默认值，Python 代码中零引用），不影响实际取数路径，勿被其误导

**与现有免费源的配合**：Tushare 更适合做**日K/历史数据补齐**（积分档位覆盖），实时快照仍应优先腾讯（60 只/次批量）；两者可通过 DataCenter 缓存分层（daily 3600s）自然衔接。

## 4. 主源与备源架构

### 4.1 调研线设计（system/02）

```
东财 push2 →（超时3s/解析失败）→ 新浪 →（失败）→ 腾讯 →（全失败）→ 本地缓存
```

- **东财 push2 主源**：`GET https://push2.eastmoney.com/api/qt/stock/kline/get?secid=0.000011&klt=101&fqt=0&lmt=120`，返回 11 字段字符串数组（日期,开,收,高,低,成交量(手),成交额,振幅%,涨跌幅%,涨跌额,换手率%）；换手率东财直给，是筹码算法核心输入
- **备源缺失字段处理**：新浪/腾讯无换手率 → 用静态流通股本表自算；腾讯默认前复权，接入时必须与东财不复权逐日校准（至少 20 个交易日，偏差 >0.5% 弃用）
- **地域选择**：ECS 必须选华东/华北地域，海外地域访问东财有人机验证风控

### 4.2 产品线实现（SourceManager，代码实证）

四源统一调度：`akshare`（封装东财/腾讯/新浪）、`eastmoney`、`tencent`、`sina`。

| 数据类型 | 产品当前优先级（data/source.py） | docs/15 建议调整 |
|---|---|---|
| stock_list | [akshare] | — |
| realtime | [eastmoney, tencent, akshare] | **[tencent, sina, eastmoney, akshare]**（东财降到最后） |
| etf | [akshare] | — |
| daily | [akshare, eastmoney, tencent] | [akshare, eastmoney, tencent] |
| minute | [akshare, tencent] | **[sina, tencent, akshare]**（新浪慢但稳，分钟K 最优） |

**调整理由**：① 东财 burst 封禁是实测事实，不应作为实时首选；② 腾讯 60 只/次批量对全市场扫描最省请求数；③ 新浪分钟K 实测最稳。

**容错机制**（SourceManager）：连续错误 3 次 → 该源冷却 300s；随机延迟 0.5-2.0s；全局限流 20 次/分钟；快照缓存 24h 陈旧回退（标记 `_stale/_fallback/_age_seconds`）；股票列表含 5 只硬编码兜底。

**缓存分层**（DataCenter）：quote 60s / all_realtime_quotes 30s / daily 3600s / stock_list 86400s / minute 300s；非交易时段直接返缓存。

## 5. 数据质量闸门

每次拉取落库前过三道校验，任何一道不过则该只该日标记 `suspect`，不进入信号计算：

| 校验 | 规则 |
|---|---|
| 逻辑校验 | 最高≥最低、最高≥开盘/收盘、最低≤开盘/收盘；OHLC 四价 >0 |
| 跳空校验 | 开盘价与前收偏离 >±11%（非一字板）→ 标记人工复核（可能是除权或数据错误） |
| 单调性校验 | 与前一日收盘价偏离 >±11% 且非涨跌停 → 标记 |

**除权日处理**：价格断层且成交额断层时，该日及其后 1 日信号标记 `div_adj`；当日可知指标照常计算，筹码分布 D(t) 递推在除权日重置网格。

**产品线增强**：DataValidator 对股票数据 5 类校验、市场数据、信号、计算范围分别校验，Redis 持久化 validation 历史。

## 6. 时点纪律（与回测对齐的硬约束）

```
15:00 收盘 → 15:05 引擎读全量日K（含当日）→ 自算指标 → 生成信号（T日信号）
次日 09:25 推送执行提醒 → 用户开盘下单（T+1 成交）
```

- ECS 系统时区必须 `Asia/Shanghai`
- 产品线盘中扫描只在交易时段运行（beat.py `is_trading_session` 判断），非交易时段不产生新信号

## 7. 配置项

```yaml
data:
  primary: eastmoney_push2      # secid 规则：深市 0. 沪市 1.（688 科创板也用 1.）
  fallback: [sina, tencent]
  fqt: 0                        # 不复权，锁定
  klt: 101                      # 日K
  history_len: 120              # 覆盖 MA60 + 20日新高 + 5日量比
  request_interval_ms: 400      # 限流
  timeout_s: 3                  # 单源超时即 failover
  retry: 2
pool:
  main: config/pool_main.json   # 17 只
  ext: config/pool_ext.json     # 10 只
index:
  code: "000001.SH"             # 上证指数（R13）
  secid: "1.000001"
fundamentals:
  file: config/fundamentals.json # PE/ROE 快照，财报季更新
```

产品线 `.env` 相关项：`TUSHARE_TOKEN`（2026-10-16 已填入应急 token，策略见 §3.5）、`REDIS_HOST/PORT/DB/PASSWORD/SSL`。`DATA_SOURCE` 为遗留字段（代码零引用，勿被其误导）。
