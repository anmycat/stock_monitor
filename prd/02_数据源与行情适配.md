## 1. 口径总原则：与回测完全一致

全部规则的验证基于**不复权日K**，指标由日K自算。任何数据源、任何加工环节偏离这个口径，信号即失效。

| 维度 | 规定 | 违反后果 |
|---|---|---|
| 复权 | 一律不复权 | 前复权会改写历史价格，MA/RSI/筹码分布全部偏移 |
| 频率 | 日K（实时路径为分钟级快照，仅用于盘中提醒，不产生回测口径信号） | 分钟K混入日K信号破坏"当日可知"纪律 |
| 指标来源 | 引擎自算（MA5/MA20/RSI/KDJ/量比/筹码） | 外部指标接口有陈旧快照风险（教训：neodata 估值快照 PE 错误） |
| 时区 | 东八区（Asia/Shanghai） | 跨日错位，信号日与成交日整体偏移一天 |

### 3.2 东财封禁事件详解（重要风险发现）

- 首轮 3 家均 200 成功；连续 burst 后东财全部失败（0/15），表现为 TCP 层直接拒连（"Remote end closed connection without response"，非 HTTP 错误码）
- 暂停 65 秒后仍未恢复；更换域名（push2delay / 80.push2）同样被封
- **解读**：东财对突发流量极敏感，触发的是 **IP 级风控**而非频次软限制。全市场扫描类系统（pz=5000 + 循环刷新）极易踩雷

### 3.3 慢速接口的合理用法（对应"允许慢速接口"）

分钟K/日K等非实时路径不参与盘中决策，可用慢源 + 本地缓存，把慢源对系统的影响降到零。新浪分钟K 0.36-0.71s 实测可用，适合收盘后/低频路径。

### 3.5 Tushare Pro 应急源配置（2026-10-16 登记）

**定位原则：收费源，只做应急，不做主力。免费源（腾讯/新浪/东财/akshare）恢复正常后立即切回。**

| 项 | 值 |
|---|---|
| Token | 已配置于 `coding/quant_engine/.env` 的 `TUSHARE_TOKEN`（用户 2026-10-16 提供，全文见 .env，本文不复制明文） |
| MCP 服务 | `https://api.tushare.pro/mcp/?token=<token>`（模型上下文协议入口，供 AI 工具直连） |
| HTTP API | `https://api.tushare.pro`（POST，字段 `api_name`/`token`/`params`/`fields`） |
| 积分档位 | 120（注册 100 + 完善资料 20），恰好覆盖日线等基础行情接口 |

**切换纪律**：
1. 免费源全部不可用（腾讯/新浪/东财 burst 封禁 + akshare 同源失效）时，才允许切 Tushare
2. 切换是**手工操作**：代码中当前**没有 tushare 通路**（`data/sources/` 仅 eastmoney/tencent/sina 三源 + akshare_source，`TUSHARE_TOKEN` 在 Python 代码中零引用），实际启用前需先写 `TushareSource` 适配器（实现 `data/source.py` 的 Source 接口）并注册进 SourceManager——**已列为迭代 B7**（14 计划 §3），验收：免费源全部不可用时自动切换、unit test mock 通过
3. 免费源恢复后切回，并把 Tushare 调用量压到最低（积分即额度，burst 浪费）
4. `.env` 中 `DATA_SOURCE=tushare` 是**遗留字段**（config.py 默认值，Python 代码中零引用），不影响实际取数路径，勿被其误导

**与现有免费源的配合**：Tushare 更适合做**日K/历史数据补齐**（积分档位覆盖），实时快照仍应优先腾讯（60 只/次批量）；两者可通过 DataCenter 缓存分层（daily 3600s）自然衔接。

### 3.6 天天基金持仓接口（ETF 持仓成分股监控，2026-10-18 实测）

**定位**：ETF 持仓成分股监控（01 §7.3）的**唯一数据源**，非行情源、不参与信号计算。代码：`quant_engine/data/sources/fund_holdings.py`（`EastMoneyFundHoldingsSource`）。

| 项 | 值（2026-10-18 实测口径） |
|---|---|
| 接口 | `GET https://fundf10.eastmoney.com/FundArchivesDatas.aspx?type=jjcc&code=<6位基金代码>&topline=<N>&year=<YYYY>` |
| 请求头 | 必须带 `Referer: https://fundf10.eastmoney.com/ccmx_<code>.html`（东财系风控要求） |
| 返回 | `var apidata={ content:"<HTML>", arryear:[...], curyear:... }`；content 内含**该年度全部季度**的持仓表（每季一个 box，倒序），字段：股票代码/名称/占净值比例/持股数(万股)/持仓市值(万元) |
| 频率 | 季报披露后更新（季度结束后的 2-3 周内某日）；每日盘后检查一次即可 |
| 解析 | 正则按季度区块拆分；最新季度的行另含"最新价/涨跌幅"两个 **JS 占位 span（无实值）**，解析取每行最后三个有效数值 |
| 代码规范化 | 东财 `0.300750`→`300750.SZ`、`1.600519`→`600519.SH`、`4/8` 前缀→`.BJ` |

**实测发现的三个坑（均已写入代码注释与 10 风险登记）**：

1. **topline 上限约 100**：`topline=100` 稳定返回每季前 100 大；**`topline≥200` 被服务端静默降级为 10**——监控统一用 100
2. **不带 topline 只返回空表头**（季度框在、tbody 空，懒加载），勿用此形态做解析
3. **数据源质量瑕疵（2026Q1）**：510300 两季反推净值跳变 −52.6%、588000 的 2026Q1 仅 48 行——按年请求的全部季度数据中，**最新季度数据可信、个别历史季度存在源端不一致**。监控层以"两季反推净值跳变 >50% 记 warning + 推送文案标注"兜底（01 §7.3 ETF-H6），权重类告警不受影响

**等价封装**：akshare `fund_portfolio_hold_em(symbol, date)` 包装同一接口（按年返回、含季度列），本项目未走 akshare 路径（本地 venv 未装 akshare，直连可单测）。

**降级策略**：接口失败 → 当日检查跳过（下次盘后重试），已有 Redis 快照继续供 API 展示；无备用源（季报持仓无第二免费源），失败只落日志不推送（宁缺毋滥，与 07 §9 故障矩阵一致）。

### 3.7 财经新闻多源接口（早间财经新闻推送，2026-10-18 实测）

**定位**：早间 9:15 财经新闻推送（01 §7.4）的数据源。代码：`quant_engine/data/sources/news_sources.py`（`NewsSourceManager` + 6 个适配器）。原则：**尽量多源、单源故障自动降级、不因任何单源失败放弃当日推送**。

| 源 | 接口 | 状态 | 关键字段 |
|---|---|---|---|
| 东财快讯 | `np-weblist.eastmoney.com/comm/web/getFastNewsList?client=web&biz=web_724&fastColumn=<101重要\\|102全球\\|103公司>&sortEnd=&pageSize=50&req_trace=<任意串>` | ✅ 常驻 | `data.fastNewsList[]`：code/showTime/title/summary；详情页 `finance.eastmoney.com/a/{code}.html` |
| 同花顺快讯 | `news.10jqka.com.cn/tapp/news/push/stock/?page=1&tag=&track=web&pagesize=50` | ✅ 常驻 | `data.list[]`：id/title/digest/ctime(unix秒)/url/tagInfo(标签)/stock(关联股票) |

| X(Twitter) | `api.x.com/2/tweets/search/recent`（Bearer Token） | ⚠️ 需凭据，默认关闭 | `data[]`：id/text/created_at；需 X Developer 免费档以上 |
| 通达信 MCP | `NEWS_TDX_MCP_ENDPOINT` + `NEWS_TDX_MCP_API_KEY`，JSON-RPC `tools/call` → `wenda_news_query` | ⚠️ 需凭据，默认关闭，**首次启用需人工核对返回结构** | MCP `result.content[0].text`（JSON 或纯文本，两种均已适配） |

**实测不可用（2026-10-18，勿再试，防止重复劳动）**：

- **财联社电报**：`cls.cn/nodeapi/updateTelegraphList` 全 404（新版需签名验证，成本高放弃）
- **金十数据**：`flash-api.jin10.com` 502（需私有头部鉴权）

**已实测的接口坑（写入代码注释）**：

1. **东财 getFastNewsList 必须带 `req_trace` 参数**（任意字符串），否则返回 `Required String parameter 'req_trace' is not present`

4. **新浪 rich_text 以【标题】开头**，需拆出标题与正文，否则整段成为标题

**降级策略**：单源失败（网络/限流/结构变更）只记 warning，其余源照常；三源全失败的当日不推送（宁缺毋滥）。各源 `pageSize=50`、每日 9:15 抓一次（单次总量上限 120 条），请求量远低于东财风控阈值（burst 风险见 §3.2）。

### 3.8 数据源重组：腾讯/新浪一线、东财备路（2026-10-20 用户决策）

**背景**：东财出口 IP 经常被风控（ECS 实测 error_count=22 连败、本进程 0 请求；本地亦多次限流），且原架构有两条**断裂的数据链路**未被发现：

| 链路 | 原状 | 后果 |
|---|---|---|
| `stock_list` | 仅 akshare 一条路，本地/ECS 均未安装 | 退化为 `CompositeSource` 5 只兜底股票 |
| `daily` | 仅 akshare 实现了 `get_daily_data`（东财/腾讯彼时无此方法），akshare 未安装 | **signals 恒空**（`/api/signals` 返回 `[]` 的直接根因） |
| ETF 行情 | `etf_monitor` 直调 `AKShareSource().get_etf_quotes()` | ETF 监控全量"数据获取中" |

**用户决策（2026-10-20）**：① 东财降为备路，腾讯/新浪互为第一线配合；② 继续遵守"只在交易时间内取数据运算（新闻推送除外）"。

**新增能力实测要点（已写入代码注释）**：

1. 新浪列表接口返回 JSON（UTF-8，中文 `\u` 转义，**不需要 GBK**）；`symbol` 行首前缀 `sh/sz/bj` 即权威市场标识（北交所无需单独 node，`hs_a` 全覆盖）

- `utils/calendar.is_trading_time` 维持原口径 **9:30-11:30 / 13:00-15:00**（不含集合竞价），监控运算（burst/信号/大盘分析/ETF 行情）严格遵守——非交易时段 `get_all_realtime_quotes` 恒返空

**清华 CSLT 说明**：用户提及"清华行情网站"作为第一线候选——经核查，公开语境中"清华"与行情仅有两个关联：① CSLT 的 K_data 接口（**校内 NFS 导入，ECS/公网不可达**，2026-10-19 调研结论）；② 清华 pip 镜像源（安装加速，非行情）。未发现公网可用的清华行情网站，故第一线按腾讯/新浪落地；若用户有校内访问权限可再评估其作权威日线交叉校验源（CodeGuard 场景）。

## 4. 主源与备源架构

### 4.1 调研线设计（system/02）


## 5. 数据质量闸门

每次拉取落库前过三道校验，任何一道不过则该只该日标记 `suspect`，不进入信号计算：

| 校验 | 规则 |
|---|---|
| 逻辑校验 | 最高≥最低、最高≥开盘/收盘、最低≤开盘/收盘；OHLC 四价 >0 |
| 跳空校验 | 开盘价与前收偏离 >±11%（非一字板）→ 标记人工复核（可能是除权或数据错误） |
| 单调性校验 | 与前一日收盘价偏离 >±11% 且非涨跌停 → 标记 |

**除权日处理**：价格断层且成交额断层时，该日及其后 1 日信号标记 `div_adj`；当日可知指标照常计算，筹码分布 D(t) 递推在除权日重置网格。

**产品线增强**：DataValidator 对股票数据 5 类校验、市场数据、信号、计算范围分别校验，Redis 持久化 validation 历史。

### 5.1 代码-市场解析口径（2026-10-18 事故修复，01 §7.5）

**事故背景**：原三源均有隐式市场推断，导致「代码与实际股票不匹配」——腾讯 `code.startswith('6')` 把 5 开头的沪市 ETF（510300/518880）错判 `.SZ`；东财 clist/ulist 与新浪的 `else 判 SZ/SH` 把北交所（8/4/920 开头，920819 实测）错判。同股双码造成 `quote:{code}` 缓存分裂、ETF 监控匹配失效、持仓 diff 键错乱。

**修复口径（唯一真相 `utils/code_utils.py`）**：

| 场景 | 解析依据 | 说明 |
|---|---|---|
| 腾讯行情 | 行首 `v_sh510300=` / `v_bj920819=` 自带市场前缀 | 最权威，直接提取；同时修复 GBK 中文名解码（`response.encoding='gbk'`） |
| 东财 ulist/clist | `f13` 市场字段（1=沪）+ 代码前缀规则细分 | **f13=0 不等于深市**——北交所在东财体系 f13 同样为 0（920819 实测），须按前缀细分 BJ/SZ |
| 新浪行情 | 行首 `hq_str_bj920819=` 前缀映射 | 实测新浪支持 `bj` 前缀；GBK 解码 |
| 天天基金 F10 HTML | 静态前缀规则 `MARKET_RULES` | 唯一无市场字段的场景，规则表：SH=6/5/9，SZ=0/1/2/3，BJ=4/8/92（含 920 新段） |
| 东财 secid 转换 | `to_secid`：沪市 `1.`、深市与北交所共用 `0.` | 920819 用 `0.920819` 查询实测有效 |

**已实测的代码坑（写入代码注释）**：

1. **北交所 920819 在东财 f13=0**（归深市场组），任何"f13=0 即 SZ"的写法都会错判
2. **腾讯行情返回 GBK 编码**，不显式设置 `response.encoding` 中文名全是乱码（新浪同）
3. **ETF/LOF（5 开头）是沪市**，`startswith(('0','3'))→SZ else SH` 与 `startswith('6')→SH else SZ` 两套旧规则都会把 510300 错判
4. **北交所 secid 与深市共用 `0.` 前缀**，`0.920819` 查询有效；`to_secid` 不可按市场分前缀

**CodeGuard 守护**（01 §7.5）：盘前 9:00-9:15 静态校验（格式/市场标记/存在性/名称）+ 集合竞价 9:15-9:25 缓存连续性校验（竞价价 vs `quote` 缓存昨收跳空 >11% 判定串号），market_mismatch 自动修复脏缓存。新数据源接入时的代码解析必须走 `code_utils`（review 检查项），否则 G28 风险复发。

**⚠️ 实时行情出口卫生断言缺口（13 报告 §4.4 实证，B5 待修）**：2026-10 东财冷却期，实时快照 `change_pct` 出现异常值 → `/api/market` 返回"100 只全涨、均涨 11.35%"、警报文案出现不可能的"超过100%的股票上涨"、`/api/validation` 报警"平均涨跌幅异常 11.25"（成功率 0%）。上述三道闸门只覆盖**日K落库前**，实时行情出口（all_realtime_quotes 直出 Redis）没有夹紧。**v1.5 迭代 B5**：`change_pct` 夹紧 ±10.5%（科创板/创业板 ±20%）、breadth 比例夹紧 0–100%、价格 >0；断言不过则该批次标记 suspect 并回退 24h 快照。
