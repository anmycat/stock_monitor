## 4. 审计驱动的流程固化

1. **重组后单一事实源**：prd/ 下仅保留 15 个模块文件（.qoder IDE 元数据已于 10-16 二轮清理删除，映射表留痕）；旧文件已删除（内容全部并入新文件），避免未来信息冲突
2. **数字带版本**：所有验证结论标注 rules 版本（v1.4）与数据修复状态；引用旧数字必须同时标注"已修订"
3. **双轨不调和**：产品实现线与调研方法论线的差异并列呈现并标注来源，禁止擅自统一
4. **读取受限留痕**：未能合并的内容在正文明确标注"读取受限/待补齐"，不静默省略
5. **证伪归档**：被证伪/被撤销的结论必须保留旧结论 + 数据缺陷说明 + 旧数字（rules `_6m_validation_superseded` 模式），防止未来重复"发明"
6. **数字唯一事实源 + 状态表述带核实日期**（D29 教训）：文档中的参数/性能/进度数字必须能回溯到唯一事实源（代码实证 / rules JSON / git 状态），修订时同步全路径；"领先 N 个提交未推送"类状态表述必须带核实日期，否则任务推进后静默变假（本轮 9 处部署债表述因此过期）
