## 0. 存储选型（双轨说明）

| 线 | 选型 | 理由 |
|---|---|---|
| 调研线设计 | **SQLite 单文件**（`data/stock.db`，WAL 模式，不用 ORM） | 单文件零运维，与 FC/ECS 均可打包带走；每日 dump 即备份；建表 SQL 内嵌脚本，依赖为零 |
| 产品线实现 | **Redis 8.0.5**（缓存层，256MB / allkeys-lru / RDB 快照）+ 内存态（SignalTracker/PortfolioManager 内存存储 + Redis 持久化 portfolio:positions/trades） | 实时扫描高并发读；systemd 管理，监听 127.0.0.1:6379 仅本地 |

两套选型并存是事实：调研线是方法论验证的存储设计，产品线按实时系统需求演进为 Redis。**信号/持仓的字段契约（§2-4）两线通用。**

## 1. 调研线表结构（SQLite）

### 1.1 klines — 日K缓存（数据层唯一事实源）

```sql
CREATE TABLE klines (
    code TEXT NOT NULL,            -- '300308.SZ'
    date TEXT NOT NULL,            -- 'YYYY-MM-DD'
    o REAL, h REAL, l REAL, c REAL,
    prev REAL,                     -- 前收盘（不复权）
    pct REAL,                      -- 涨跌幅%
    amp REAL,                      -- 振幅%
    vol REAL,                      -- 成交量（手）
    amount REAL,                   -- 成交额（元）
    turn REAL,                     -- 换手率%
    source TEXT,                   -- eastmoney/sina/tencent/cache
    suspect INTEGER DEFAULT 0,     -- 数据质量闸门标记（见02 §5）
    fetched_at TEXT,
    PRIMARY KEY (code, date)
);
CREATE INDEX idx_klines_date ON klines(date);
```

- 只存不复权；指标一律不落库（每次从本表现算，保证"当日可知"可复现）
- `suspect=1` 的记录：信号引擎跳过并在周报中列出

### 1.2 signals — 信号表（T 日生成，全生命周期可追溯）

```sql
CREATE TABLE signals (
    signal_id TEXT PRIMARY KEY,    -- S-YYYYMMDD-<code>-<rule>
    signal_date TEXT NOT NULL,     -- T 日（信号生成日）
    code TEXT NOT NULL,
    name TEXT,
    direction TEXT,                -- long
    rule TEXT NOT NULL,            -- R01..R13/C01..C05（规则ID）
    rule_name TEXT,
    rating TEXT,                   -- A/B/C/D（四级校准，见04 §5）
    confidence TEXT,               -- high/medium/low
    capital_tag TEXT,              -- SC-01/HC-01/YZ-01/DR-01
    regime TEXT,                   -- bull/neutral/bear（R13 输出）
    entry_low REAL, entry_high REAL,
    stop_loss REAL, take_profit REAL,
    position_pct REAL,             -- Kelly 输出，百分数，0<position≤25
    reason TEXT,
    executable INTEGER,            -- T+1 开盘校验结论 0/1
    exec_note TEXT,                -- '开盘涨停'/'除权跳空'等
    sim_pnl_pct REAL,              -- 按信号价模拟成交的盈亏%
    created_at TEXT,
    UNIQUE (signal_date, code, rule)   -- 幂等：同日重跑只更新
);
```

### 1.3 positions — 持仓状态机（无券商接入的核心）

```sql
CREATE TABLE positions (
    pos_id INTEGER PRIMARY KEY AUTOINCREMENT,
    signal_id TEXT REFERENCES signals(signal_id),
    code TEXT NOT NULL, name TEXT,
    state TEXT NOT NULL,           -- PENDING / OPEN / CLOSED / CANCELLED
    open_date TEXT,                -- T+1
    open_price REAL,               -- 回报价；未回报=区间中值（模拟成交）
    shares INTEGER,
    is_sim INTEGER DEFAULT 1,      -- 1=模拟成交 0=真实回报
    close_date TEXT, close_price REAL,
    close_reason TEXT,             -- 止损/目标/倒T接回/派发离场/人工
    pnl_pct REAL,                  -- 不复权口径
    updated_at TEXT
);
```

状态流转：

```
PENDING ──成交回报/模拟成交──→ OPEN ──卖出/止损/目标──→ CLOSED
   │                            │
   └──开盘作废(一字板/跌停)──→ CANCELLED
```

- `OPEN` 持仓每日 15:30 重算：DR-01 派发→减仓建议；R06 倒T→做T建议；R10 冻结→停开新仓
- 止损/目标按**日K收盘价**判定（与纪律一致，不用盘中价）

### 1.4 events — 事件日志（可观测性）

```sql
CREATE TABLE events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ts TEXT NOT NULL,
    level TEXT,                    -- info/warn/error
    kind TEXT,                     -- signal_generated/pushed/fill_report/fetch_fail/risk_freeze
    ref_id TEXT,                   -- signal_id / pos_id
    detail TEXT                    -- JSON 字符串
);
```

### 1.5 config_snapshot — 配置快照（复现性）

```sql
CREATE TABLE config_snapshot (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ts TEXT, rules_version TEXT, rules_hash TEXT, adopted_config TEXT
);
```

**每次信号生成前落一条快照**——复盘"当时为什么出这个信号"时，规则库可能已改，快照是唯一答案。

## 2. Signal 契约（引擎→推送的唯一出口）

### 2.1 调研线契约

```json
{
  "signal_id": "S-20261014-300308-R01",
  "code": "300308.SZ", "name": "中际旭创",
  "direction": "long", "rule": "R01", "rule_name": "动量突破买入",
  "rating": "B", "confidence": "high",
  "capital_tag": "HC-01", "regime": "neutral",
  "signal_date": "2026-10-14",
  "entry_range": [10.20, 10.50],
  "stop_loss": 9.80, "take_profit": 11.50,
  "position_pct": 15.0,
  "reason": "连涨2日+量比1.8+突破20日高点",
  "executable": true, "exec_note": ""
}
```

字段口径：`position_pct` 为**百分数**（15.0 即 15%）；`entry_range` 为 T+1 开盘可接受区间。

### 2.2 产品线 Signal（models/signal.py）

- 动作：**BUY / WATCH / SKIP**
- 级别：**S / A / B**（level_factor：S=1.0 / A=0.7 / B=0.4）
- 字段含：kelly_position、confidence、source（信号来源策略）、id 属性
- 融合规则：策略分 70% + 因子分 30%；因子分 <40 拒 BUY，<55 降级 WATCH

## 3. 成交回报协议（人工执行回写）

用户回复文本 → 解析 → positions 表：

```
B 300308 10.35 5000      # 买入：方向 代码 成交价 股数
S 300308 11.80 5000      # 卖出
```

- 解析容错：全角/半角、空格/逗号分隔、代码带不带 `.SZ` 均可
- **未回报**：按 `entry_range` 中值记模拟成交（`is_sim=1`），持仓跟踪照常，卡片标 `模拟持仓`
- 回报纠正：同方向同代码再次回复覆盖上次
- 回报超时：T+3 仍未回报的 PENDING 自动转 CANCELLED 并在周报统计"人工执行率"

**产品线对应**：PortfolioManager（Position 记录、add/close/update_prices、绩效统计，Redis 持久化 portfolio:positions/trades）。

## 4. 产品线模型与 Redis Key 规范

### 4.1 模型（models/）

| 模型 | 内容 |
|---|---|
| MarketType / MarketState | 市场类型枚举 + 状态（factor：BULL 1.0 / BULL_WEAK 0.7 / SIDEWAYS 0.5 / BEAR 0.2） |
| Signal | 见 §2.2 |
| StockQuote | 行情快照 |
| MarketRegimeDetector（hmm_detector.py） | GaussianHMM 5 状态（深熊/弱熊/震荡/弱牛/强牛）；特征=收益率/振幅/量变化率；fit/predict/get_market_factor；hmmlearn 缺失时回退 state=2 震荡 |

### 4.2 Redis Key 规范（PRD_COMPLIANCE_v2 §9）

| Key 格式 | TTL | 说明 |
|---|---|---|
| `quote:{code}` | 60s | 实时行情缓存 |
| `scan:{code}:{minute}` | 300s | 分钟线缓存 |
| `signal_cooldown:{code}:{date}` | 14400s（4h） | 信号冷却（CooldownManager：cooldown_hours=4；键带日期后缀，跨交易日自然重置） |
| `idempotent:{hash}` | 3600s | 幂等性控制（1h） |
| `stock_list` | 86400s（24h） | 股票列表缓存（DataCenter.get_stock_list 实证 ttl=86400） |
| `ai_summary:{type}` | 1800s | AI 总结缓存（30 分钟） |
| `market_state` | 300s | 市场状态缓存 |
| `sector_data` | 300s | 板块数据缓存 |
| `etf_holdings:*` | 见 §4.3 | ETF持仓快照/diff（2026-10-18） |
| `news:*` | 见 §4.4 | 早间新闻去重指纹/摘要/板块分布（2026-10-18） |
| `etf_holdings:{code}:{quarter}` | 400d | ETF 单季持仓快照（01 §7.3，code 为 6 位无后缀代码） |
| `etf_holdings:latest:{code}` | 7d | 最新季度摘要（quarter/report_date/updated_at/holdings_count/top10） |
| `etf_holdings:changes:{code}` | 120d | 最近一次季度环比 diff 结果（含 alert_count） |
| `etf_holdings:check_date` | 2d | 每日检查去重（worker 盘后任务） |
| `api_cache:etf_holdings` | 300s | API 层总览缓存（与 api_cache:etf 同模式） |

Redis 配置：版本 8.0.5、最大内存 256MB、淘汰策略 allkeys-lru、持久化 RDB 快照、监听 127.0.0.1:6379。

### 4.3 ETF 持仓键结构（services/etf_holdings_monitor.py，2026-10-18）

**持仓记录**（`etf_holdings:{code}:{quarter}` 数组元素，来自 02 §3.6 解析）：

```json
{"code": "300308.SZ", "name": "中际旭创", "weight": 4.75,
 "shares": 354.65, "market_value": 450401.94, "seq": 1, "report_date": "2026-06-30"}
```

**diff 结果**（`etf_holdings:changes:{code}`，`ETFHoldingsMonitor.diff_quarters` 产出）：

```json
{
  "previous_quarter": "2026Q1", "current_quarter": "2026Q2",
  "current_report_date": "2026-06-30", "previous_report_date": "2026-03-31",
  "new_entries": [{"code", "name", "direction": "new", "weight", "market_value"}],
  "exits":       [{"code", "name", "direction": "exit", "prev_weight", "market_value"}],
  "increased":   [{"direction": "up",   "shares_change_pct", "weight_delta", "..."}],
  "decreased":   [{"direction": "down", "shares_change_pct", "weight_delta", "..."}],
  "unchanged_count": 46, "nav_change_pct": -0.5259, "alert_count": 138
}
```

**字段口径**：weight/shares/market_value 单位为 %、万股、万元（与源接口一致，不做换算）；`shares_change_pct` 为相对变化（0.15=+15%）；`weight_delta` 为百分点差（0.2=+0.2pct）；`nav_change_pct` 为两季反推净值变化（>50% 绝对值触发数据质量 warning，02 §3.6 坑 3）。阈值常量（SHARE_CHANGE_THRESHOLD 0.10 / WEIGHT_CHANGE_THRESHOLD 0.30 / MIN_MARKET_VALUE 1000 万元）为类属性，测试可覆盖。

### 4.4 早间新闻键结构（services/news_monitor.py，2026-10-18）

**Redis 键清单**（均无 Redis 时降级为进程内内存，功能不中断）：

| 键 | TTL | 内容 |
|---|---|---|
| `news:check_date` | 2天 | 当日日期（YYYY-MM-DD），worker 9:15 任务每日只执行一次 |
| `news:last_push_at` | 7天 | 上次推送窗口终点（ISO 时间），下次抓取的时间窗起点；周一自动覆盖周末 |
| `news:seen` | 48h | 去重指纹列表 `[{h,t,s}]`（h=规范化标题SHA1前16位，t=规范化标题，s=来源），上限 600 条滚动 |
| `news:latest` | 7天 | 最近一次推送摘要（digest 全量，供 `/api/news/latest`） |
| `news:sectors` | 7天 | 板块分布摘要（含未展示板块计数，供 `/api/news/sectors`） |

**digest 结构**（`news:latest` / `NewsDigestResponse`）：

```json
{
  "generated_at": "2026-10-18T09:15:03", "window_start": "...", "window_end": "...",
  "from_last_push": true, "total": 87, "dedup_dropped": 23,
  "sector_count": 21, "hidden_sectors": 13, "hidden_items": 56,
  "sources": {"东财快讯": 45, "同花顺": 25, "新浪财经": 17},
  "sectors": [{"sector": "全球市场", "count": 47, "shown": 6, "truncated": true,
               "items": [{"time": "22:19", "source": "同花顺", "title": "...", "url": "..."}]}]
}
```

**字段口径**：`total` 为去重后保留条数；`dedup_dropped` 为时间窗内被剔除条数（精确+近似+跨次）；`hidden_*` 为推送文案限量（单板块 6 条 / 8 板块 / 15000 字符截断，01 §7.4 N5）之外的条数，**后台 API 可见、钉钉文案只显示计数**；未匹配板块关键词的条目归入"综合要闻"（分组恒末位）；`from_last_push=true` 表示时间窗起点取自上次推送（周一覆盖周末），false 表示回看默认 20h。

**去重指纹说明**：规范化 = 去空白/标点/`【】`前缀/大小写（`normalize_title`）；近似去重为 difflib 相似度 ≥0.85（`NEWS_DEDUP_THRESHOLD` 可调），并有长度差预筛（>35% 直接跳过比对）控制耗时；同一事件多源报道按 source_rank（东财1>同花顺2>新浪3>RSS4>X5>通达信6）保留最高优先级源。

### 4.5 代码一致性守护键结构（services/code_guard.py，2026-10-18）

**Redis 键清单**（均无 Redis 时降级为进程内内存，校验功能不中断、仅丢跨重启记忆）：

| 键 | TTL | 内容 |
|---|---|---|
| `code_guard:check_date_static` | 2天 | 盘前静态校验最后执行日期（YYYY-MM-DD），worker 9:00-9:15 每日只跑一次 |
| `code_guard:check_date_auction` | 2天 | 集合竞价校验最后执行日期，worker 9:15-9:25 每日只跑一次 |
| `code_guard:report` | 7天 | 最近一次校验报告（mode/checked/quoted/issues/by_type/duration，供 `/api/system/code-guard/report`） |
| `code_guard:names` | 7天 | 权威 code→name 映射（name_mismatch 时沉淀，供下游展示选用） |

**校验范围（collect_targets 三路聚合）**：① HOT_ETFS 常量（14 只，来源 hot_etf，手写简称跳过名称校验）② ETF 持仓快照成分股（`etf_holdings:latest:*` → 最新 quarter → `etf_holdings:{symbol}:{quarter}` 两跳聚合）③ `stock_list` 缓存全市场列表（格式合法性）。

**report issues 元素结构**：`{severity: error|warning, type: invalid_format|missing|market_mismatch|name_mismatch|bad_price|price_gap, code, name, message, detail, repaired?}`；market_mismatch 的 detail 含 `correct_code`，name_mismatch 含 `auth_name`，price_gap 含 `cached_price/auction_price/gap_pct`。

**修复语义（对 quote 键的写操作）**：market_mismatch → 删 `quote:{错码}`、用权威数据写 `quote:{正确码}`（TTL 300s 临时键，等真实行情刷新）；price_gap → 删 `quote:{code}` 等下周期刷新。**仅动行情缓存，不动配置与持仓快照**（快照是历史事实）。

## 5. 与规则库的映射关系

| 规则库键 | 本模型落点 |
|---|---|
| R01-R06（交易规则） | signals.rule / entry_range / stop_loss / take_profit |
| R07-R10（风控） | events(kind=risk_freeze) + positions 状态流转 |
| R11 市赚率 | 选股层：PR>0.8/亏损股的代码不进 signals（负面清单） |
| R12 预期差 | **默认关闭**（半年证伪其环境依赖性） |
| R13 牛熊 | signals.regime + "指数 bias20≤−2% 禁 R05"变体 |
| C01-C05（筹码） | C01 选股参考进 reason；C02 仅观察不进 signals；C03/C04 禁买过滤 |
| kelly 参数 | signals.position_pct |

> 规则库 `methodology_rules.json` 是配置的唯一事实源；本模型是运行时状态的唯一事实源。二者通过 `config_snapshot` 关联。
