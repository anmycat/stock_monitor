## 1. 系统是什么

### 1.1 一句话定义

**股票机器人（量化扫描系统 V5）**：一个运行在阿里云 ECS 上的 A 股量化信号系统——通过多源行情接口发现交易机会，经反信号过滤、门控模型、多策略引擎、八因子评分、HMM 市场状态识别与 Kelly 仓位计算产生信号，通过 Web UI / WebSocket / 钉钉等多渠道推送，由人工执行。全部信号逻辑可回测、可复现、可后验。

### 1.2 产品定位演进（PRD v3.0）

从"数据展示工具"进化为"决策辅助系统"：动态自适应扫描、多智能体投票、游资行为监控。部署目标：**彻底杜绝"暂无结果"，确保任何行情下均可输出有效决策参考**。迭代依据：内部代码审计 + 53k Star 级开源项目对标 + 实战反馈（22 日周期逻辑）+ 游资监控专项设计。

## 2. 系统边界

### 2.1 做什么

- **盘中实时扫描**：全市场行情多源聚合 → 反信号过滤（高位/连涨/假突破/弱势排列）→ 门控模型（趋势+资金+触发+分钟触发）→ 策略引擎（趋势/低吸/防守 + YAML 策略）→ 八因子评分融合 → Kelly 仓位 → 信号
- **市场状态识别**：HMM 五状态（深熊/弱熊/震荡/弱牛/强牛）驱动因子权重与策略权重自适应
- **风险管理**：信号冷却 + 幂等去重 + 动态止盈止损 + 相关性控制 + 连续亏损熔断 + 独立断路器层（PRD 设计）
- **监控与推送**：ETF 监控、板块监控、热钱监控、市场预警、AI 总结（早盘/全日）、WebSocket 实时推送、钉钉/企微/飞书/Telegram 四渠道通知
- **回测与后验**：回测引擎 + 抗过拟合检查 + 样本外评估 + 信号跟踪（7/30/90 日窗口）
- **交互**：Web UI（Apple 设计风格）+ Agent 问股（规则意图识别）

### 2.2 不做什么（明确边界）

| 边界 | 说明 |
|---|---|
| **不接入券商自动下单** | 系统生产信号，人工执行（PRD_COMPLIANCE 与调研线一致） |
| **不预测涨跌** | 输出的是规则信号与概率优势（胜率/盈亏比/Kelly），不是价格预测 |
| **不保证收益** | 全部规则经过实盘验证但有窗口依赖性，历史表现不预示未来 |
| **调研线特有边界** | Phase 1 不做全市场扫描（候选池固定 27 只）、不做分钟级盘中预警、信号日 T 收盘后计算 T+1 开盘成交（当日可知纪律）——此为方法论验证口径，与产品盘中实时扫描的差异见 01 §1 |

### 2.3 运行环境约束

- 部署目标：阿里云 ECS 常驻（2C2G 级，实际部署 8.134.89.55）
- 数据通道：多源 HTTP 行情接口（akshare 封装 + 东财/腾讯/新浪直连），Redis 8.0.5 缓存层
- 依赖：Python 3.11+ / FastAPI / Uvicorn / Pandas / NumPy / AKShare / TA-Lib / Redis / httpx / loguru
- 时区：Asia/Shanghai（ECS 系统时区，cron/定时任务按东八区）

## 3. 总体架构

### 3.1 产品六层架构（PRD_COMPLIANCE_v2 + 代码实证）

```
┌─────────────────────────────────────────────────────────────────┐
│ 展示层   Web UI（UX/static/index.html，Apple Design System）       │
│          + WebSocket /ws 实时推送（增强版：优先级堆/gzip/自适应频率）│
├─────────────────────────────────────────────────────────────────┤
│ API 层   FastAPI（main.py，2 workers，端口 8000）                  │
│          REST 27 路由 + X-API-Key 认证 + Swagger /docs            │
├─────────────────────────────────────────────────────────────────┤
│ 调度层   beat.py（盘中监控循环 120s）+ worker.py（Celery 阶段任务） │
│          MORNING_REVIEW 11:30-11:35 │ DAILY_REVIEW 15:00-15:05   │
├─────────────────────────────────────────────────────────────────┤
│ 服务层   signal_generator（扫描/单股）│ market_analyzer（HMM）     │
│          etf/sector/hot_money/burst 监控 │ market_alert 预警       │
│          ai_summary（DeepSeek+MiMo 双模型）│ agent_router 问股      │
│          notifiers（钉钉/企微/飞书/Telegram）                      │
├─────────────────────────────────────────────────────────────────┤
│ 策略层   StrategyDispatcher ─┬─ 单股路径：AntiSignalFilter→GateModel│
│          （registry 统一注册）│   → 内置策略（Trend/Dip/Defense）   │
│                            └─ 全市场路径：ThreeLayerFunnel         │
│                               → YAML 策略×3 → FactorScorer 八因子  │
│                               → LLMRanker（可选）→ 深度分析 Top N  │
│          融合规则：策略分 70% + 因子分 30%；因子<40 拒 BUY，<55 降级 │
├─────────────────────────────────────────────────────────────────┤
│ 数据层   SourceManager 统一调度（akshare/eastmoney/tencent/sina）   │
│          容错：3 次错误→300s 冷却 │ 随机延迟 0.5-2.0s │ 20 次/分钟  │
│          快照陈旧回退（24h 标记）│ DataCenter 分层缓存              │
│          Redis（quote 60s / daily 3600s / minute 300s / …）       │
├─────────────────────────────────────────────────────────────────┤
│ 风控层   RiskManager（止损 5%/回撤 10%/连亏 3）│ PositionSizer     │
│          （Kelly）│ StopLossManager │ CorrelationManager          │
│          RiskBucket（CVaR 熔断）│ CooldownManager（4h+幂等）       │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 调研方法论线的信号生产流水线（rules v1.4 结构，v1.5 参数）

```
① 数据层    日K（不复权）+ 指数 + 基本面快照 → 质量闸门（三道校验）
② 因子层    指标自算（MA/RSI/KDJ/量比/位置）+ 筹码分布 D(t) 递推
③ 资金层    SC-01 慢资金 / HC-01 起爆 / YZ-01 游资 / DR-01 派发 属性判定
④ 射程层    规则 × 资金属性 查矩阵，不在射程 → 丢弃
⑤ 过滤层    R11 选股负面清单 → R13 急跌禁低吸变体 → 评级校准（A/B/C/D）
⑥ 仓位层    Kelly 半凯利 × 相关性折扣 × 25% 上限，负期望 → 0 仓
   → Signal 契约 → 推送
```

## 4. 核心设计哲学（PRD v3.0 六维变更）

| 维度 | v2.0 旧理念 | v3.0 新理念 |
|---|---|---|
| 筛选机制 | 绝对硬阈值（评分≥70） | **自适应相对强度**（22 日滚动分位数 + 市场系数） |
| 市场识别 | 规则判断（牛/熊/震荡） | **HMM 五状态** + 外围环境加权 |
| 决策方式 | 单引擎计算 | **多智能体投票**（技术派+资金派+风控官一票否决） |
| 信息展示 | 长列表罗列 | **结论先行**（气象卡 → 焦点区 ≤3 只 → 折叠流水区） |
| 风险管控 | 策略内置逻辑 | **独立断路器层**（Guardian Service，一键熔断） |
| 数据驱动 | 仅量价数据 | **量价 + 新闻情感 + 龙虎榜游资**三维共振 |

## 5. 核心机制（PRD v3.0）

### 5.1 自适应阈值漏斗（替代固定过滤）

不问"绝对分高不高"，只问"比过去一个月强不强"：

| 层级 | 功能 | 实现逻辑 | 状态 |
|---|---|---|---|
| L0 市场画像 | 确定调节系数 | HMM 五状态 + 离岸人民币/A50 隔夜；牛市系数 1.2（防追高），熊市 0.7（捕超跌） | ✅ |
| L1 动态基准 | 个股及格线 | 过去 22 个交易日评分的 70% 分位数为基准，今日评分 > 分位数×市场系数即通过 | ✅ |
| L2 多周期验证 | 防假突破 | 10 日（短线）/22 日（波段）/60 日（趋势）三周期相对强度加权投票 | ✅ |
| L3 保底机制 | 杜绝"暂无结果" | 全市场无通过 L1-L2 时，输出涨幅/量比排名前 5 异动股，标"资金异动观察池" | ✅ |

### 5.2 多智能体投票引擎（三委员）

| 角色 | 职责 | 输入特征 | 权限 |
|---|---|---|---|
| 委员 A（趋势派） | 技术形态与动量 | 均线排列、MACD、ATR | 推荐/不推荐 |
| 委员 B（资金派） | 真金白银流向 | 主力净额、大单动向、北向资金 | 推荐/不推荐 |
| 委员 C（风控官） | 持仓风险与市场环境 | 波动率、板块集中度、总回撤 | **一票否决权** |

决策规则：A+B 同荐且 C 通过 → 强烈推荐（置顶焦点区）；A 或 B 单一推荐 → 观察池；C 否决 → 丢弃并标注"风控拦截"。（PRD 状态：70% 设计完成，待开发）

### 5.3 游资监控模块

- **龙虎榜智能分析**（盘后 17:00 更新）：席位画像库（华鑫上海分公司、国君江苏路等风格标签）；🟢 游资合力（买入前五 ≥3 知名游资且买入额>卖出额 2 倍）/ 🔴 游资出逃 / 🔵 机构接盘
- **盘中大单异动**：逐笔大单量超过去 20 日均值 3 倍标准差 → 极端异动警报；连续 3 笔以上 >500 万元同向 → 主力突击建仓
- **游资情绪仪表盘**：活跃度（今日上榜数/20 日平均）、做多情绪（净买入/净卖出）、连板成功率（昨日首板今日晋级率）

### 5.4 独立断路器层

| 熔断等级 | 触发条件 | 强制执行动作 |
|---|---|---|
| 🔴 一级熔断 | 组合总回撤 > 8% | 冻结所有新开仓信号，仅允许平仓，直至回撤修复至 5% 以下 |
| 🟡 二级预警 | 单日账户浮亏 > 2% | 所有新开仓仓位自动减半 |
| 🟢 常规风控 | 单票仓位 > 40% 或板块 > 30% | 自动拒绝相关信号开仓申请 |

## 6. 信息架构与 UI（详见 07 §8）

- **顶部气象卡**：今日大盘状态 + 建议总仓位 + 今日最佳策略（HMM + 外围加权），固定悬浮
- **中部焦点区**：仅 ≤3 只股票——触发价 vs 现价偏离、科学止损止盈位、买入置信度（天时/地利/人和）
- **底部流水区**：其他普通信号与游资异动流，折叠面板
- 信号卡片强制三大决策参数：触发价/现价/博弈位置、建议动作、止损/目标 1/目标 2
- UI 设计语言：Apple Design System（Action Blue #0066cc 唯一交互色、SF Pro、17px 正文、负字间距、药丸徽章、无阴影极简）
