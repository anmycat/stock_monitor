## 3. 调度（双轨）

### 3.1 调研线 cron（东八区）

```cron
30 9  * * 1-5   python3 main.py open_check    # 竞价后开盘价校验 + 执行确认推送
5  15 * * 1-5   python3 main.py signal        # 收盘计算 → 信号生成 → 推送
30 15 * * 1-5   python3 main.py persist       # 数据落库 + 备份 + 健康检查
0  16 * * 0     python3 main.py weekly        # 周报
```

工程要点：交易日判断（主源返回当日有日K才是交易日，holidays.json 兜底，非交易日直接退出）；幂等（`(signal_date, code, rule)` 唯一索引）；失败告警走邮件兜底渠道。

### 3.2 产品线调度（beat.py + worker.py）

- **beat.py**：盘中监控循环——`is_trading_session` 判断 → `analyze_market` → 市场状态变更推送 → sleep 120s
- **worker.py**：Celery 阶段任务——MORNING_REVIEW（11:30-11:35 早盘总结，之后 sleep 1800s）/ DAILY_REVIEW（15:00-15:05 全日总结，之后 sleep 3600s）
- **ETF 持仓变化检查（2026-10-18 新增）**：worker 非交易时段分支（else）调用 `check_etf_holdings(datacenter, notifier)`——遍历 14 只热门 ETF 抓取季度持仓，发现新季度则 diff，过阈值的变化走 `notifier.send_custom_message` 推送；`etf_holdings:check_date` 保证**每日一次（含周末，季报披露日不固定）**；14 只 × 2 个年度请求约 30-60s，单日一次可接受；接口失败当日跳过不推送（02 §3.6 降级策略）
- **早间财经新闻推送（2026-10-18 新增）**：worker 非交易时段分支（else）调用 `check_morning_news(datacenter, notifier)`——执行窗口 **9:14-9:35**（覆盖交易日前 PRE_MARKET 与非交易日 WEEKEND，周一自动覆盖周末新闻），`news:check_date` 每日只推一次；时间窗 = 上次推送时刻起（无记录回看 20h），抓取三源（东财快讯/同花顺/新浪7×24）→ 三层去重 → 关键词板块分类 → 限量 markdown 文案走 `notifier.send_custom_message`；三源全失败当日不推送；总耗时约 5-15s（3 源 × pageSize 50），9:15 前可完成
- **代码一致性盘前校验（2026-10-18 新增，01 §7.5）**：worker 非交易时段分支（else，覆盖 PRE_MARKET）调用 `check_code_guard_static(datacenter, notifier)`——交易日 **9:00-9:15** 窗口内执行（`code_guard:check_date_static` 每日一次），对 HOT_ETFS + ETF 持仓快照成分 + stock_list 做格式/市场标记/存在性/名称四重校验，权威源腾讯批量 50 只/次（约 1100 目标 → 22 批 × 0.15s 间隔 ≈ 5s）；market_mismatch 自动删错键写对键；全绿不推送，有问题才推钉钉
- **代码一致性集合竞价校验（2026-10-18 新增）**：worker SELF_CHECK 分支（9:15-9:25）在刷新活跃池后调用 `check_code_guard_auction(datacenter, notifier)`——`code_guard:check_date_auction` 每日一次；用竞价虚拟匹配价与 `quote:{code}` 缓存昨收做连续性校验，跳空 >11% 判定缓存串号并清理；同时该分支**补跑** `check_morning_news`/`check_etf_holdings`（check_date 幂等），防止 PRE_MARKET 循环错过 9:14 窗口的极端情况
- **AI 总结定时推送**：早盘总结 11:35、全日总结 15:05，钉钉 + WebSocket 双推（PUSH_MECHANISM_GUIDE）；PRD_COMPLIANCE 记载时间优化为 12:15/18:15（避开 DeepSeek 涨价时段）
- **交易时间判断**：上午 9:30-11:30、下午 13:00-15:00；收盘后 15:00-15:30 推送最后一期数据，前端显示"已收盘"

## 4. 执行闭环

### 4.1 调研线四段（人工执行被显式建模）

```
① T日 15:05  收盘计算 → 生成信号卡片 → 推送「预信号」
② T+1 09:25  集合竞价后 → 开盘价校验 → 推送「执行确认」
③ T+1 盘中    用户手动下单 → 可选回报 → 系统记录成交
④ 持仓期      每日推送「持有 / 加 / 减 / 清」建议
```

**T+1 开盘可执行性预检**：开盘一字涨停→"放弃或排队，勿市价追"；开盘跌停→信号作废；开盘在入场区间→可执行；开盘跳空超上限 3%→放弃；停牌→跳过；前收突变 >15% 非涨跌停→"疑似除权跳空，人工确认"。

### 4.2 产品线闭环

- 信号生成（signal_generator）→ 风控检查 → Kelly 仓位 → 幂等 hash → BUY 时多渠道推送
- 盘中不产生回测口径新信号；分钟触发门控仅用于盘中提醒
- Agent 问股（agent_router）：规则意图识别（analyze_stock/hotspots/list_strategies/market_overview/scan_signals/evaluate/free_chat），session 30 分钟 20 轮

## 5. 推送渠道（四渠道 + 消息类型）

### 5.1 渠道实现（services/notifiers/）

| 渠道 | 机制 | 配置项 |
|---|---|---|
| 钉钉（主） | HMAC-SHA256 加签 + markdown 消息 | `DINGTALK_WEBHOOK` + `DINGTALK_SECRET` |
| 企业微信 | Webhook | `WECHAT_WEBHOOK_URL` |
| 飞书 | interactive card | `FEISHU_WEBHOOK_URL` |
| Telegram | Bot API | `TELEGRAM_BOT_TOKEN` + `CHAT_ID` |

钉钉签名实现：`timestamp = str(round(time.time()*1000))`；`string_to_sign = '{}\n{}'.format(timestamp, secret)`；HMAC-SHA256 → base64 → quote_plus；URL 追加 `&timestamp=&sign=`。消息类型支持 text/markdown/link/actionCard/feedCard。

### 5.2 推送类型与触发（DINGTALK_CONFIG_REPORT + PRD_COMPLIANCE）

| 类型 | 触发条件 |
|---|---|
| 交易信号 | 策略扫描到买入/卖出信号，评分 ≥70，通过风控检查 |
| 市场异动 | 板块涨跌幅异动、热钱流向变化、涨停/跌停数量、市场情绪指数 |
| ETF 监控 | 溢价/折价率、成交量异常、价格突破（14 只目标 ETF） |
| ETF 持仓变化 | 季报新季度披露后：新进/退出/增持/减持过阈值（数量/方向/权重/市值，01 §7.3 ETF-H4） |
| 早间财经新闻 | 每日 9:15（含周末）：多源抓取 → 去重 → 按板块分组的要闻摘要（01 §7.4） |
| AI 总结 | 定时任务（早盘/全日） |
| 系统状态 | 服务启停、异常错误告警、数据源连接失败 |

### 5.3 去重与频率控制（最佳实践，代码已实现）

- **消息去重**：`hashlib.md5(message)` + Redis `setex(cache_key, 3600, "1")`，1 小时内不重复发送
- **消息分级**：INFO/WARNING/CRITICAL，critical 级 @所有人
- **频率控制**：RateLimiter（默认 10 条/小时/类型），避免消息轰炸
- **信号冷却**：CooldownManager 4 小时（`signal_cooldown:{code}:{date}`）+ 幂等 md5 hash 1h

## 6. WebSocket 增强推送（api/websocket_enhanced.py）

### 6.1 服务器主动 Push 机制（PUSH_MECHANISM_GUIDE v2.1，2026-06-10）

**实现**：WebSocket 服务器端定时循环推送，main.py 导入 websocket_enhanced 替代原 websocket。

| 数据类型 | Push 频率 |
|---|---|
| 市场数据（market_update） | 60 秒 |
| 大盘异动（alert） | 30 秒 |
| 交易信号（signals） | 5 分钟 |
| ETF 状态（etf_update） | 60 秒 |
| 板块热度（sector_update） | 2 分钟 |
| 游资动向（hot_money_update） | 2 分钟 |

**收盘后处理**：`is_closed = t >= 15*60`，市场类型显示"已收盘"（灰色背景），涨跌家数定格在 15:00 数据。

### 6.2 Gzip 压缩与自适应 Push 频率（WEBSOCKET_OPTIMIZATION v2.2，2026-06-12）

**Gzip 压缩**：消息 >1KB（`compression_threshold = 1024`）自动压缩，级别 6，Base64 编码传输，前端 Pako.js CDN 自动解压；压缩统计日志每 100 条输出。预期：带宽节省 40-70%，单日节省 ~2.5MB（单用户），CPU 开销 <0.005%。

**自适应频率**：市场活跃度计算（0-100 分）= 涨跌家数变化率 ×0.4 + ETF 涨跌幅绝对值 ×0.4 + 近期异动数量 ×0.2；滑动窗口平均（最近 10 次）；每 60 秒检查一次。

```python
if avg_activity > 70:    multiplier = 0.5   # 高活跃：50% 间隔
elif avg_activity > 50:  multiplier = 0.75  # 中高活跃
elif avg_activity > 30:  multiplier = 1.0   # 中等活跃
else:                    multiplier = 2.0   # 低活跃：200% 间隔
```

**连接管理增强**（代码实证）：优先级堆（ALERT/AI_SUMMARY=0 最高）、2 秒批量 10 条、增量更新、活跃度自适应频率（线性回归预测）、scan/scan_stock/ping/chat 消息处理。

### 6.3 前端 Web 修复（WEB_FIX_REPORT v2.1，2026-06-12 10:52 CST）

**修复的问题**：
1. **涨跌家数不更新**——前端调 `/api/market` 取 `data.up/down`（字段不存在），实际应调 `/api/market/sentiment` 取 `up_count/down_count`；修复后 1 分钟刷新
2. **大盘异动 Web 不显示**——原 5 分钟轮询且未用 WebSocket；修复后新增 WebSocket 连接（断开 3 秒自动重连）+ 异动去重（`alertCache[type_timestamp]`，最多保留 20 条）+ 30 秒轮询兜底

**分层刷新策略**：1 分钟（市场数据/指数）+ 30 秒（异动）+ 5 分钟（信号/板块/ETF/热钱/评估）。

**新增功能**：WebSocket 状态指示器（实时推送/连接失败/断开）、异动数量计数器、异动时间显示、滑入动画、自动缓存清理。

**性能对比**：涨跌家数更新 从不更新 → 1 分钟；异动延迟 5 分钟 → 实时（WebSocket）+ 30 秒（轮询），10 倍提升。

## 9. 故障恢复矩阵（双轨合并）

| 故障 | 检测 | 恢复动作 | 用户可见 |
|---|---|---|---|
| 主数据源挂 | 超时 3s/解析失败 | 自动切备源（产品线：SourceManager 3 次错误→300s 冷却） | 信号卡标 `⚠ 数据陈旧至 X 日` |
| 单源 IP 封禁（东财实测） | 连续失败 | 熔断开 + 限流 20 次/分钟 + 绝不高频重试 | 透明切换，不静默 |
| 主备源全挂 ≥2 日 | 健康检查 | 推送告警邮件 | `数据中断告警` |
| 单只票拉取失败 | 缺口表 | 指数退避重试 2 次；仍失败该只该日不进信号 | 该只当日无信号（不静默） |
| 快照陈旧 | 24h 快照年龄 | 回退缓存数据并标记 `_stale/_fallback/_age_seconds` | 显式标注 |
| 规则引擎异常 | 非零退出 | 告警 + 当日不推送（宁缺毋滥） | `引擎异常，今日无信号` |
| 钉钉推送失败 | HTTP 非 200 | 重试 3 次 → 邮件兜底 | 邮件收到同样卡片 |
| 进程崩溃 | systemd Restart / 平台 | 自动重启；重启后幂等补跑 | 无感 |
| 误推送/重复推送 | 唯一索引 + 推送前查重 | 同日同票同规则只推一次 | 无 |
| WebSocket 断开 | onclose | 前端 3 秒自动重连 | 状态指示器显示"断开" |
| ETF持仓接口失败（天天基金 jjcc） | 请求异常/非 200/解析失败（2 次重试） | 当日检查跳过，已有 Redis 快照继续供 API；下次盘后重试；**无备用源，失败只落日志不推送**（02 §3.6） | 当日无持仓变化推送（不静默丢历史数据） |
| ETF持仓源端数据异常（两季反推净值跳变 >50%） | diff 内断言 | 记 warning + 推送文案显式标注"持股数变化或含数据源异常"，权重类告警仍有效 | 文案带 ⚠️ 标注 |
| 早间新闻单源失败（东财/同花顺/新浪） | 请求异常/非200/JSON解析失败（各源 2 次重试） | 单源隔离：只记 warning，其余源照常推送；**三源全失败当日不推送**（宁缺毋滥） | 来源统计行可看出缺源 |
| 早间新闻源接口变更（如东财改键名/改参数） | 解析结果为空或字段缺失 | 与单源失败同路径降级；02 §3.7 已登记实测坑（req_trace 必需、fastNewsList 键名），接口再变更需重新实测 | 来源统计缺该源 + 日志 warning |
| 早间新闻推送窗口错过（worker 重启跨过 9:35） | check_date 未记 | 当日跳过不补推（新闻时效性已过，补推无意义），次日正常 | 无（符合预期） |
| 早间新闻 Redis 不可用 | cache get/set 抛错或返回 None | 降级进程内内存：批内去重/窗口推进仍有效，跨次去重失效（可能少量重复） | 去重剔除数下降 |
